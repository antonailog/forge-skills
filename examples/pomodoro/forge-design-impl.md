# forge-design-impl

## 输入

- forge-dev 调度进来：设计阶段已完成（`.features/pomodoro-timer/status.md` 里 design 为「已完成」，DESIGN.md 评分 A−）。
- 设计真相源 `docs/DESIGN.md`；工作台导出的组件 token `pomodoro.tokens.css`（勿手改）；工作台骨架 `docs/assets/visuals/pomodoro/2026-10-23-skeleton-v1.0.html`；决策文件 `docs/assets/visuals/pomodoro/pomodoro.tokens.json`（里面配好了「骨架和真页面自动比对」的清单）。
- 行为契约 `.features/pomodoro-timer/feature-spec.md`；forge-dev 本轮的 `docs/v1.0-CONTEXT.md`（灰区默认值）和 `docs/v1.0-RESEARCH.md`（建议的文件划分、「样式与行为的接口」）。
- 观感参考：两张气质稿 `docs/assets/visuals/pomodoro/mood/`。
- 项目里还没有任何页面代码。

## 用户会怎么说

「设计定了，按 DESIGN.md 把页面做出来，先只做样子，不写逻辑。」

## 过程

0. **准备**：读项目指引、文档入口和索引、DESIGN.md、Feature Spec、两份 forge-dev 产物。Skill 没说在哪个分支干活，按 forge-eng 的工作区规矩从主分支拉出一个隔离副本（`.worktrees/pomodoro-timer`，分支 `eng/pomodoro-timer-2026-10-23`），后面 forge-eng 接着用。功能状态文件里加一行「设计实现·进行中」。
1. **识别实现清单（第 1 步）**：DESIGN.md 是全新页面，清单就是整页：
   - 页面结构：计时区、控制区、记录区、贴底的存储提示区；静态内容就是第一次打开的样子（专注、25:00、开始、跳过、今天完成 0 个）；给阶段、剩余时间、主按钮、跳过、完成数五个元素挂上比对锚点。
   - 站点 token：原始色、语义色、系统字体写进样式文件开头。
   - 页面框架：不滚动、单列居中、光学上移、提示区贴底并避开手机底部横条。
   - 组件样式：阶段标签、等宽数字的剩余时间、始终占一行的状态说明、阶段色主按钮、弱化的跳过、完成数、存储提示，以及悬停和键盘焦点。
   - 状态切换：只靠页面上的两个属性（现在是专注还是休息、能不能保存）切颜色和提示。
   - 响应式与无障碍：窄屏、矮屏两档换小字号，系统开了「减少动态效果」时不过渡。
   - 视觉参照：气质稿只看气质；实现后要拿真实截图对比的状态是首次打开、专注进行中、已暂停、专注到点、休息进行中、不能保存，以及手机竖屏、手机横屏。
   - 演示时由 AI 按默认确认：实现清单照上面执行，分成「结构与站点 token」「布局、组件、状态与断点」两份任务交给 Codex，各自一个提交。
2. **定「样式与行为的接口」**：下一棒 forge-eng 写行为时只改属性和文字，不碰样式。接口写在样式文件开头的注释里：一个属性管阶段（专注 / 休息），一个属性管存储提示出不出现；状态说明不设属性，直接改文字、留空就是没字；另外列出 forge-eng 要改的几处文字。
   - 演示时由 AI 按默认确认：接口只用这两个属性（最简单的方案），不为「进行中 / 已暂停」另设属性，因为它们在页面上只是文字不同。
3. **实现（第 2 步）**：Skill 要求 Claude Code 把样式代码交给本机 Codex 写（codex-delegate），Claude 写任务书、验收、提交。两份任务书都写明以 DESIGN.md 哪几节为准、组件只能用 token、不许加非目标里的东西，并把工作台骨架里已经验收过的那段样式指为几何参照。Codex 两份任务都是一轮交回、一轮验收通过；它在自己的沙箱里打不开浏览器，所以截图验收全部由 Claude 来做。
   - 演示时由 AI 按默认确认：DESIGN 写的「页面不滚动」在所有常见屏幕上做到；极小的窗口宁可滚动也不裁掉内容（Feature Spec 要求不截断）。
4. **逐项自检、原子提交（第 3 步）**：每份任务交回后读完整改动、对照任务书逐条核对、在真页面上看，通过后各提交一次，提交信息注明「由 Codex 实现」和作业编号。
5. **质量验证（第 4 步）**：
   - 起本地服务，用无头浏览器打开真页面，用属性和文字切出六种状态，在桌面大屏、笔记本、手机竖屏（含很窄的小屏）、手机横屏下截图。
   - 读浏览器算出来的样式逐项核对：字号、字重、行高、颜色、按钮尺寸和圆角、各块之间的间距、悬停变色、键盘焦点框、「减少动态效果」时不过渡，全部和 DESIGN、token 一致；切状态时按钮和完成数的位置纹丝不动；所有屏幕上元素都在一屏内、不重叠、没有滚动条；控制台零错误，没有向外部网址发任何请求。
   - 用设计工作台自带的比对脚本，把骨架和真页面放在同一个桌面尺寸下逐个比五个锚点的位置和尺寸：全部对上；两张整页截图逐像素完全相同。
   - 检查样式里有没有写死的颜色和字号：颜色只出现在开头的 token 定义里，尺寸数字只出现在两条断点里，组件规则全部引用 token。
   - 反 AI 模板扫描：没有渐变、阴影、卡片、图标、装饰动画。Skill 的反模板清单里有一条「暖色纸底 + 土红点缀」，和 DESIGN 定的「纸面安静」接近；Skill 规定 DESIGN.md 是唯一真相源、有异议回 forge-design，所以照 DESIGN 实现并在这里记一笔。
   - 演示时由 AI 按默认确认：按 DESIGN 实现，不回 forge-design 重开配色。
   - 关掉本地服务，确认端口释放、没有残留进程。功能状态文件里「设计实现」标为已完成。

## 问题

- **Skill 默认「已经有页面，只改样式」**：简介写「只改样式不改逻辑」，清单举例是「把卡片圆角改大一点」这类小改动，原则是「能用 CSS 解决的不改 HTML 结构」。全新项目连页面都没有，这一步实际是先搭整页结构；Skill 没说新页面怎么做，也没要求给后面的行为代码留接口（属性名、钩子）。这次接口是调度器在任务里点名要的。
- **没说在哪个分支、哪个目录提交**：只写「原子提交」。forge-eng 有隔离副本的规矩，这次照它建的；状态文件模板里也没有「设计实现」这一行，要自己加。另外 forge-eng 指南里「检查隔离目录有没有被 git 忽略」的命令，在目录还没建出来时会误报「没忽略」，照做会往主分支多提交一行重复的忽略规则。
- **完成框写「下一步：forge-qa」**：在 forge-dev 的顺序里，设计实现之后是工程实现。页面还没有行为，QA 没法测。
- **反 AI 模板清单和上游设计打架**：本 Skill 把「暖色纸底 + 土红点缀」列为 AI 默认审美，还要求标题和正文用不同字体家族；forge-design 定的恰好是暖纸底 + 砖红、全页一种系统字体（PRD 不许加载外部字体），它的 AI 模板痕迹评分还是 A。两个 Skill 的反模板标准不一致，实现阶段只能照做、记一笔。
- **最有力的检查不在 Skill 里**：第 4 步只说「对比 DESIGN.md 和实际渲染」「grep 硬编码」，没提设计工作台已经备好的骨架比对脚本；这次是靠 DESIGN.md 的实现交接一节和调度器提醒才跑的，而它恰恰给出了最硬的证据。
- **「grep 硬编码」「Token 引用率」都没给口径**：断点里的数字、`0`、`none`、整屏高度算不算硬编码，引用率的分母是什么，都没说；照字面搜颜色关键字还会把 `white-space` 当成白色。这次口径是自己定的。
- **一部分内容和这个项目无关**：组件选型指向 shadcn/ui、Tailwind，无障碍要求里有弹窗焦点锁定、表单标签，纯静态单页都用不上，要读的人自己判断跳过。
- **非交互运行没法弹确认**：第 1 步「向用户展示清单，确认后开始」只能由 AI 代答。
- **样式由 Codex 写，但它看不到页面**：Codex 的沙箱里启动不了浏览器，验收脚本和比对脚本都跑不了，样式等于「盲写」，好不好看全靠 Claude 截图把关（派活细节见 codex-delegate 的记录）。
- **不适合宣传的点**：这一步顺利得近乎照抄——两份任务都一次通过，是因为工作台骨架里已经有一段验收过的样式可以直接搬。宣传时适合讲「设计在工作台定死、实现自动核对」，不适合讲「AI 一次就写出了好看的样式」。
