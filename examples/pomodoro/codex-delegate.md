# codex-delegate

## 输入

不是用户直接叫起来的，而是在两个 Skill 走到「写代码」这一步时被调用：

- forge-design-impl 第 2 步：把 `docs/DESIGN.md` 和工作台导出的 `pomodoro.tokens.css` 落成页面结构和样式。
- forge-eng 第 7 步：按 `docs/ENGINEERING.md` 拆好的任务，把计时规则、页面接线、到点提醒写出来。

两次都在同一个隔离副本 `.worktrees/pomodoro-timer`（分支 `eng/pomodoro-timer-2026-10-23`）里进行；Codex 只能改这个副本，改完由 Claude 验收、提交。

## 用户会怎么说

真实使用时通常不用说，forge-eng、forge-design-impl 进入写代码步骤会自动用它。用户主动说的话是：「这几个任务派给 Codex 写，你来验收。」

## 过程

1. **预检（第 0 步）**：确认自己是 Claude Code、确认在隔离副本里、工作区干净；跑一次环境检查，确认本机 Codex 程序和代理都在。环境检查访问外网时返回的是「被拒绝」，查明这是网站对命令行工具的正常拦截，代理本身是通的，不是故障。
2. **写任务书（第 1 步）**：一个任务一份，放在隔离副本的 `.forge/jobs/` 下（不进仓库）。按 Skill 的模板分「背景 / 任务 / 验收标准 / 范围 / 检查点 / 收尾」几节，这次一共写了五份：
   - 设计实现两份：「页面结构与站点 token」「布局、组件、状态切换与断点」。任务书点明以 DESIGN.md 哪几节为准、组件只许引用 token，并把设计工作台骨架里已经验收过的那段样式指为几何参照。
   - 工程实现三份：「纯计时规则与单元测试」「页面接线」「到点提醒」。规则那份要求严格先写测试，并**提前告诉 Codex 会怎么查它**：会把实现换成什么都不做的空壳，测试必须全部失败；会把关键规则故意改坏，每一处都必须有测试报警。
   - 每份的验收标准都写成能判对错的条目：哪条命令必须成功、哪些写法一处都不许出现（例如外部网址、写死的颜色、系统通知）、只许改哪些文件。
   - 每份都写明「不要提交、不要推送、不要留下后台服务」，提交由 Claude 来做。
3. **派活（第 2 步）**：五份任务前后有依赖，按顺序一份一份派，前一份验收通过再派下一份。
4. **判活（第 3 步）**：每份都等到完成。Skill 写的「阻塞等待」时长超过了 Claude Code 单条命令的上限，改成分段等待。五份都正常跑完，没有卡死、没有空交。
5. **收结果（第 4 步）**：Codex 每次交回「改了哪些文件、跑了哪些检查、请你重点看哪里」。两份前端任务都如实写了「浏览器在我的沙箱里打不开，页面检查没跑，请你来验」。
6. **验收（第 5 步）**：Claude 每份都读完整改动、亲自重跑任务书里的检查，前端部分再在真实浏览器里看：
   - 设计实现：在多种屏幕尺寸下截图、逐项核对浏览器算出来的字号颜色间距，再用设计工作台的比对脚本把骨架和真页面逐个元素对齐——完全重合。
   - 计时规则：把实现换成空壳，测试全部失败；把关键规则逐处改坏，每处都被测试抓到；另按 Feature Spec 独立写了一份检查，也全部通过。
   - 页面接线和到点提醒：用无头浏览器加「假时钟」把一段专注快进完，逐条验开始、暂停、跳过、到点、刷新恢复、跨零点、不能保存、两个页面等场景，全程没有控制台错误、没有外部请求。
   - 验收中发现的小瑕疵都没到返工的程度：第一份的注释里留了临时任务编号，顺手放进下一份任务书里一起改；页面接线里多包了一层错误捕获，Claude 设法复现「会吞掉错误」没复现出来，就记进工程文档的技术债交给审查环节，没有返工。
7. **返工 / 收回（第 5–6 步）**：五份都是一轮通过，没有返工，也没有收回由 Claude 自己写。
8. **提交与小结（第 7 步）**：每份验收通过后由 Claude 单独提交一次，提交信息注明「由 Codex 实现」和作业编号；派活小结写进了 forge-design-impl、forge-eng 各自的交付说明。

演示时由 AI 按默认确认：模型和推理强度跟随本机 Codex 的默认设置，不另外指定。

最适合截图：

- **`.worktrees/pomodoro-timer/.forge/jobs/T01.prompt.md` 的「验收标准」一屏**（首选）：能看到 Claude 怎么给 Codex 立规矩——每条都能判对错，还预告了「我会把你的实现换成空壳、把规则改坏来检查你的测试」。

## 问题

- **Codex 看不到页面**：Codex 跑在只能改工作目录的沙箱里，连无头浏览器都启动不了。前端任务等于「盲写」，好不好看、对不对齐全靠 Claude 截图把关。Skill 只泛泛说「前端改动要看真实页面」，没提醒「Codex 那边一定跑不了浏览器」，任务书只能写「沙箱里起不来就跳过、写明即可」。
- **等待写法超过上限**：Skill 示例里的阻塞等待时长，超过了 Claude Code 单条命令的最长时长，照抄会被中途打断，要自己改成分段等。
- **环境检查的结果容易误读**：检查命令访问外网返回「被拒绝」，看起来像代理坏了，其实是网站拦截命令行工具的正常现象；Skill 没说明怎么读这个结果。
- **一次通过不全是 Codex 的功劳**：五份任务全部一轮通过，主要因为上游把东西定得很死——设计实现有骨架里现成的样式可照搬，工程实现在工程文档和任务书里把接口、规则口径写到了每个函数。宣传时适合讲「Claude 定标准、亲自证伪，Codex 照图施工」，不适合讲「Codex 自己就写对了」。
- **规则任务等得明显更久**：要求先写测试、自查改坏规则的那份，Codex 认真做了全部自查，耗时比其他几份长得多。演示录屏时需要剪辑。
- **小毛病**：脚本没有帮助命令；「判活」建议用定时轮询，但在子任务里没有这个能力，只能自己分段等待。
