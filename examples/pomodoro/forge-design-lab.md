# forge-design-lab

## 输入

forge-design 第三步转交：设计方向「纸面安静」、站点级颜色与系统字体、Feature Spec 里的页面结构（计时区、控制区、记录区、存储提示、标签页标题）和全部状态。项目里还没有任何样式文件和页面代码。

## 用户会怎么说

「开工作台，按真实尺寸看看这一页怎么排。」看完改完后：「保存好了，按调整后的来。」

## 过程

1. **适配（S1）**：跑 Skill 的适配脚本找项目已有的样式。全新项目什么都没有，脚本报「没找到任何站点样式」并以失败退出，但起步的决策文件照样写出来了。于是把 forge-design 定的站点色和字体手填进决策文件；页面 token 统一用 `--pomo-` 前缀；前端要引入的那份 token 样式放在仓库根目录（PRD 建议页面文件放根目录）。
   - 项目没有「零件库」（全站设计模板），也没有现有样式可抽取；单页面项目，跳过零件库这一步。
2. **线框确认（S2）**：决策文件里只写区域、模块、状态和结构类 token，生成页面包。线框是一列居中（计时区、控制区、记录区）加贴底的存储提示区。第一次渲染时底部区域跑到了页面中间——工作台引擎自己的一条样式把线框区域压成了「跟着内容排」，在页面里补一行样式拉回来。
   - 演示时由 AI 按默认确认：区域划分、五个模块（页面框架、计时区、控制区、记录区、标签页标题）、五个状态（专注进行中、首次打开、已暂停、专注到点、休息进行中）加一个「浏览器不能保存」开关。
3. **骨架（S3）**：按七层（结构、层级、排版、色彩、间距、状态动效、一致性）补齐节点，每个可改的值都能在骨架上点到；文案用 Feature Spec 原文；页面钩子实时量出数字宽度、内容需要和可用的高度、按钮尺寸，写进七道判断题。另做一层「模块放大」：一排被挤窄的浏览器标签，加上按钮的默认、悬停、键盘焦点三种样子。Skill 的验收脚本全部通过。
   - Skill 要求用 `open` 在浏览器里打开页面；这是无界面的子任务，改用无头浏览器打开同一个页面审查。
   - 给需求方的开场：先看「番茄钟页面 · 专注进行中」；重点三题是手机横屏放不放得下、主按钮用不用阶段色、手机上两个按钮怎么排。
4. **第 1 轮审查（S4）**：起本地服务（保存直写仓库），需求方在工作台上逐层看、给结局、写反馈、点保存。
   - 演示时由 AI 按默认确认：内容列宽、光学上移、桌面数字字号、按钮过渡都保持；主按钮用阶段色；手机上两个按钮并排（不采用气质稿里的上下叠）。
   - 演示时由 AI 按默认确认：「手机字号」标为「拿不准」，并写反馈「手机横屏时『专注』被顶出屏幕」。这是工作台在手机横屏视口下实测出来的：宽度不触发手机字号，高度又放不下桌面大字。
   - AI 读保存回执：没有改值，七层都有结局，两条反馈逐条回复。针对「拿不准」新增一个「矮屏阈值」节点，出 A/B/C 三档：A 不启用（接受溢出）、B 只在手机横屏这种矮窗口换小字号、C 范围更大，把拉得很矮的笔记本窗口也算进去；每档写清能看到的后果，并推荐 B。
5. **第 2 轮审查**：
   - 演示时由 AI 按默认确认：选 B，横屏完整放下。保存后回执显示一处改值；同源校验、验收脚本再跑一遍，全部通过。
6. **交接（S5）**：
   - 演示时由 AI 按默认确认：按调整后的来。
   - 把决策文件生成成 DESIGN.md 里的 token 表区块（带「勿手改」标记）。
   - 写实现清单进 DESIGN.md：怎么引入 token 样式、断点怎么写、哪些是 token 以外的决定、给五个关键元素加比对锚点；决策文件里配好「实现比对」清单，实现后可以自动比对骨架和真页面的位置尺寸。
   - 没有「提议改动站点级 token」的节点，站点级清单为空。
   - 调用 forge-feature-doc：新写一个截图脚本，从骨架截出布局标注图、六种状态缩略图、标签页标题和按钮细节图，替换需求设计文档里原来的页面示意，删掉旧示意的源文件，「阶段」改为「设计」，关键改动加一行；文档检查通过。
   - 关掉本地服务；保存回执目录加进 `.gitignore`，不进仓库。

## 问题

- **线框层被引擎自己的样式弄乱**（最值得修）：引擎给所有带编号的元素加了「相对定位」，而线框区域一律带编号（连没有对应元素的纯布局区域也带一个空编号），于是线框里的顶层区域全部变成跟着内容排，贴底的区域跑到了页面中间。这正是 Skill 踩坑清单第 3 条，只是发生在引擎自己身上；验收脚本只数了「线框有几个区域」，没发现位置错了。
- **页面包模板自带已知坑**：模板里按钮的重置样式写法，正是踩坑清单第 16 条明说会吃掉按钮边框的那种写法。每个新页面包都会继承，需要手动改。
- **全新项目走不通适配**：适配脚本找不到站点样式就以失败退出，提示「让用户指认站点全局样式文件」——新项目根本没有。Skill 没说新项目的站点 token 从哪来。这次手填进决策文件，前端的站点样式要等实现时照 DESIGN.md 手写，恰好形成 Skill 想消灭的「看到的和实现的是两份」。
- **只能按宽度切手机布局**：引擎的手机模式只看窗口宽度。这次最有价值的发现（手机横屏放不下）是高度问题，只能在页面钩子里自己加判断绕过去。
- **判断题里的实测数字要手工回填**：题目是写死在决策文件里的文字，「带实测数字」得先渲染一遍、量出数字再写回；需求方一改值，题里的数字就过期了。
- **颜色引用节点漏写备选会让面板报错**：说明里「备选」只是建议字段，但颜色引用类节点没写备选时面板代码会直接出错。这次每个都写了，没踩到。
- **结局按钮是开关**：改值后会自动记成「改」，再点一次「改」反而把结局清空了。第 2 轮演示时踩到，补点了一次才恢复。
- **保存回执的时间不带时区**：回执里的时间是世界标准时间，和项目里其他文件的本地时间对不上，看起来像差了好几个小时。
- **和需求设计文档的出图脚本会打架**：forge-feature-doc 的出图脚本会把示意图源文件全部重新渲染并覆盖同名图片。换成骨架截图时必须删掉旧的页面示意源文件，否则下次一跑又被盖回示意图；两个 Skill 都没写这一步。
- **适合宣传的点**：横屏溢出不是靠经验想到的，是工作台在真实尺寸下量出来的；A/B/C 三档在骨架上切着看，需求方不用想象。
