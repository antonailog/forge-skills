# forge-design

## 输入

- `/forge` 的推荐：有 PRD 和 Feature Spec，还没有设计文档。
- `docs/PRD.md`、`.features/pomodoro-timer/feature-spec.md`（页面结构、状态、视觉约束）、需求设计文档 `docs/modules/番茄钟.md`。
- 需求方的审美设定：简洁、安静，不要花哨动效。

## 用户会怎么说

「开始做设计，把这个页面的设计规范定下来。要简洁、安静，不要花哨动效。」

## 过程

1. **定位文档、定门控**：项目里没有 DESIGN.md，走「创建模式」；这是一个全新页面，按分级门控属于 L1 完整设计（不可跳过）。功能状态文件里把设计阶段标为「进行中」。
   - 演示时由 AI 按默认确认：门控级别 L1。
2. **产品理解**：从 PRD 回答四问——解决什么、给谁用、成功是什么感觉（「看一眼就知道还剩多久，不看也不打扰」）、有没有参考。
3. **竞品调研**：搜了 Pomofocus、Flow、一款叫 FlowState 的浏览器插件和几个开源极简番茄钟。共性是「大号倒计时居中 + 少量按钮 + 用颜色区分阶段」；能做得不一样的地方是：不按阶段整页换背景色、不要进度环、把浏览器标签页标题当主要信息出口。
4. **三个美学方向**：
   - A「纸面安静」：暖白纸底、墨色数字、两个低饱和阶段色（专注砖红、休息灰青）、无阴影无卡片。
   - B「深色专注」：Skill 自带配色库给「番茄钟」的默认方案——深底、饱和红、绿色。
   - C「整页阶段色」：像 Pomofocus 那样每个阶段整页换背景色。
   - 演示时由 AI 按默认确认：选 A（最贴合「简洁、安静」）。
5. **配色与字体**：跑 Skill 自带的配色、字体检索。配色库的番茄钟方案是深底加红绿，字体库返回的全是要从网上加载的字体；前者不安静、红绿对色弱用户难分，后者违反 PRD「不从外部网址加载资源」。最后用自定的暖色纸墨色板加系统字体，逐个颜色算了对比度，正文和按钮文字都达到无障碍标准。
   - 演示时由 AI 按默认确认：配色与字体方案。
6. **三层 token**：原始色值 → 站点级语义色（背景、文字、两个阶段色、提醒色等）→ 页面级组件 token（交给工作台导出）。
   - 演示时由 AI 按默认确认：token 体系与页面线框。
7. **气质稿**：L1 要求出 Image 2 视觉稿。先写好 prompt（真实文案、色值、禁用风格），用本机 codex 的内置生图出了桌面、手机两张，图、prompt 和元数据一起存档。只用来判断气质，不判断比例。
   - 演示时由 AI 按默认确认：气质够安静；手机稿里按钮上下叠的画法不直接采用，交给工作台判断。
8. **设计审计**：项目还没有页面，只能审计 PRD 里的页面结构和资料库的推荐。挑出的问题：照抄资料库会出现红绿配色和网络字体；数字走秒会左右跳（要用等宽数字）；「已暂停」这行出现消失会让按钮上下跳（要始终占位）；手机底部提示要避开刘海屏的安全区；「一切居中」接近 AI 模板痕迹，但单一焦点的计时页本该居中，用光学上移和留白分组化解。
9. **第三步方案：转交 forge-design-lab**。页面布局、比例、密度、状态都在工作台的真比例骨架上定（见 [forge-design-lab.md](forge-design-lab.md)），本 Skill 只给开场线框。
10. **0-10 交互审查**：七个维度全部落在「可以直接实现」档，不需要另记待办。最弱的几项：「休息到点」没在骨架上单独画、到点那一刻页面上只有文字和颜色变化、站点色要等实现时才写进样式、提示音音色未定。
11. **写文档**：新建 DESIGN.md（美学定位、三层 token、页面布局、组件状态、交互、异常态、实现交接、已知问题）和设计变更日志（落选方向及理由、关键决策、设计评审）。DESIGN.md 里的页面 token 表由工作台生成，不手写。
12. **同步需求设计文档**：Skill 要求调用 forge-feature-doc，把「页面布局、状态一览、交互与细节」三节的图换成工作台骨架截图（细节见 forge-design-lab 记录）。
13. **质量评估与交付**：按 A-F 评分得 A−（L1 门槛是 B，放行）；扣分项是提示音音色没在设计阶段试听。AI 模板痕迹评分 A。功能状态文件里设计阶段标为「已完成」，文档入口和索引加上两份新文档。
    - 演示时由 AI 按默认确认：设计定稿，下一步交给实现。

## 问题

- **Skill 内部对效果图的要求打架**：Skill 简介和正文说效果图「只在气质方向不明时出」，创建手册却写「L1 完整设计必做」，交付前检查清单也要求「已完成视觉稿门禁」。这次按严的做了两张。
- **自带资料库和项目约束冲突，且没有提示**：字体库返回的全是网络字体，创建手册还要求「每个字体方案附 Google Fonts 链接」，但这个项目明确不许加载外部资源；配色库给番茄钟的默认方案是红绿搭配，和 Skill 自己的「不用红绿组合」规则矛盾。一次总检索还把「时尚、奢侈品」风格、蓝橙配色、养生类字体拼成一套推荐给番茄钟。不加判断照抄就会出错。
- **「新项目必须定义」的 token 清单对小页面过度**：要求阴影三档、四个断点、按钮加载态，这个页面没有浮层、只需要两个断点、按钮从不加载，只能逐项写「不定义 / 不存在」。
- **几处时长规范不一致**：审计清单、交付前清单、交互规则库给出的动画时长范围各不相同，按哪个算合格没说。
- **审计步骤默认已有页面**：第二步是「审计现有设计状态」，全新项目没有可审的东西，只能拿 PRD 的结构和资料库推荐来审。
- **站点样式没有落点**：Skill 只产出文字版 token 表，新项目里没有任何样式文件，工作台读不到站点色（见 forge-design-lab 记录），站点色要等实现时照文档手写进样式——文档和代码两处来源。
- **Feature Spec 等着回填，但没人回填**：上一棒的 Feature Spec 写着「颜色、字号、间距的具体值由 forge-design 定稿后回填到这里」，forge-design 的步骤里没有这一步。这次没改 Feature Spec，具体值以 DESIGN.md 为准。
- **非交互运行没法弹选项**：每轮确认都要求用选择框问用户，示范里只能由 AI 代选并记录。
