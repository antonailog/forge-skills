# forge-fupan

## 输入

- 番茄钟示范从头到尾的全部示范记录（本目录下 forge-doc-policy 到 forge-bugfix 的各份 `.md`），当作这次项目「会话」的完整经过。用户原话取自每份记录里的「用户会怎么说」。
- 项目仓库最新的 main：番茄钟 v1.0 已合进主分支（未部署），BF-1023-1 已修复合并。
- 复盘账本里已有的通用教训（只读对照，用来做「老毛病有没有复发」的检查）。

## 用户会怎么说

「项目做完了，复盘一下：这次哪些做法值得带走，我下次该怎么跟 AI 说。」（或者直接 `/forge-fupan`）

## 过程

按 Skill 的 v3 流程：分析经过 → 在复盘工作台（Workbench）推出学习地图 → 「用户」在独立会话页勾选知识点和深度 → 调研写作 → 落账本。

0. **准备**：确认项目仓库和远端一致、工作区干净。Skill 的素材默认是「本机最新的一份会话日志」，但这个项目是十几个 Skill 分在不同子任务里做完的，没有单独一份日志能代表全过程，所以以示范记录为素材。
1. **分析经过**：从记录里整理出工作叙事、四句值得改进的用户原话、三个行为问题、三处 AI 表现问题，以及八个候选知识点（每个都配一句人话解释和「这次在哪出现」）。
2. **推学习地图、启动工作台**：把分析结果写成学习地图，创建一个复盘会话，启动本地工作台。
   - **改道**：工作台默认把会话存进用户自己的工作台目录、从用户真实的复盘目录读文档和账本，首页会列出用户所有历史复盘。这次用工具自带的参数把会话目录和复盘目录都指到临时目录，另起一个服务（用户自己常开的那个工作台服务没碰），所以页面上只有这一个示范会话。
   - 没有用 Skill 写的「自动在浏览器里打开」，改用无头浏览器扮演用户打开独立会话页。
3. **「用户」勾选知识点**：会话页列出四句「表达待优化原话」（每句附问题和「下次可以说」）和八张知识点卡片；AI 预选了四张。
   - 演示时由 AI 按默认确认：读者设定为「想了解用 AI 做一个小项目全过程的普通人」，保留「先写需求规格和验收检查表」「写代码的和验收的要分开」「测试全过，为什么还会有问题」三个，取消「修 bug 先做实验找根因」；深度全部保持 Skill 给的推荐（前两个「表达」、第三个「了解」）。
   - 演示时由 AI 按默认确认：补充反馈写「读者是想了解用 AI 做一个小项目全过程的普通人：少用术语，多拿番茄钟里的真事举例。『修 bug 先做实验找根因』这次先不学。」
   - 点「提交学习选择」后，命令行里等待提交的那一步立刻拿到了选择结果，页面变成「生成中」。
4. **调研**：三个知识点各做了网络检索，延伸学习只放官方或权威来源：Claude Code 官方最佳实践（让 AI 先追问再写规格、给 AI 一个能跑的检查、让另一个 AI 去推翻结果）、Martin Fowler 关于 Given/When/Then 和测试覆盖率的两篇短文、GitHub Spec Kit、变异测试工具 Stryker 的说明、Chrome 官方关于后台页面计时限速的博客。
5. **知识图**：按全局规则用本机 Codex 的内置生图，两张并行出图，抽看两张文字都对。第三个知识点按示范要求控制数量，只保存了出图提示，文档里按 Skill 规定写明「图像待生成」。
6. **写复盘文档**：工作叙事、四条原话分析（每条两档更好的说法）、三个行为诊断、三个知识点、三处 AI 表现、速查表、最后八条 TLDR；逐项过了 Skill 的检查清单，文内跳转链接全部有效。按补充反馈，全文少用术语、例子都取自番茄钟。
   - **改道**：不写进用户的个人复盘目录，按文档治理白名单放进项目仓库 `docs/archive/raw/retrospectives/`（原始复盘材料），图和出图提示放同目录 `assets/`。
7. **落账本**：
   - 演示时由 AI 按默认确认：落三条——「单测全绿不算数，审查要拿测试的期望值对照口径」「待拍板要写明谁、在哪一步拍板」「修复分支合并主线后要按新规矩重落、重跑回归」。
   - **改道**：写进 `examples/pomodoro/fupan/learnings.jsonl`，不碰用户真实账本。
   - 复发检查：对照用户账本里的通用教训，「新写的检查先用已知结果验一遍」「一说准时就换成可验收的说法」「发布汇报分层写状态」这次都做到了，记为已改进；没有发现复发。
8. **收尾**：
   - 并行登记表里有一行修 bug 时留下的登记，会话编号和本次复盘相同（同一个调度会话派出的子任务共用一个编号），按 Skill「只清本会话自己的登记行」删掉了这一行；登记表只在本机、不进仓库。
   - 把复盘文档标记为完成，会话页出现「打开这次的复盘文档」入口（为此在临时目录里放了一份文档副本，原因见「问题」）。
   - 「记忆回流」和「全局复盘索引」两步写的是用户自己的全局记忆和复盘目录，示范跳过。
   - 复盘文档按路径单独提交到示范仓库 main 并推送；之后关掉临时工作台服务，确认端口释放、没有残留的浏览器进程。

**工作台有没有碰用户的真实复盘数据**：没有。会话、复盘文档副本、账本副本都在临时目录；用户自己的工作台服务、会话列表、复盘目录和账本都没被改动（事后核对它们的修改时间都早于本次运行）。

## 问题

- **复盘的落点写死在用户的个人目录（最值得修）**：Skill 开头说「遵循文档治理规范」，正文却把复盘文档、知识图、账本、索引都写死在用户个人的复盘目录，没有看项目自己的白名单（文档治理规范里明明有「原始复盘材料」这个位置）。工作台也一样：会话页的「打开复盘文档」入口和账本页只认它那一个复盘目录，文档放在项目仓库里时入口就不出现、也不报错，这次只好在临时目录里放一份副本才让入口出现。收尾的提交命令同样按个人目录写，在项目仓库里照抄会加不上文件、却照样去提交和推送当前分支。
- **工作台的改道参数没写进 Skill**：工具本身支持另指会话目录和复盘目录，但 Skill 只给默认用法；照默认跑，示范会话会混进用户自己的历史列表，截图会带出用户的其他复盘。
- **默认素材是「一份会话日志」，对多会话项目不适用**：前置脚本按修改时间取本机最新的一份日志，跨多个会话和子任务完成的项目没有单独一份能代表全过程，取到的可能是别的并行会话。Skill 给的「完整 / 恢复 / 轻量」三档都套不上「以示范记录为素材」这种情况。
- **「只清自己的登记行」认不出别的子任务**：同一个调度会话派出的子任务共用一个会话编号。这次删掉的是修 bug 时留下的那行，因为修复已经合并，删了没问题；如果修 bug 还在跑，复盘就会把它的登记当成自己的删掉。登记表模板里还写着「由复盘第 5.0 步清除」，和 Skill 现在的步骤编号对不上。
- **开头身份信息两套标准**：Skill 要求会话、迭代次数、创建和更新时间；文档治理规范要求状态、类型、模块、更新日期，类型的封闭清单里又没有「复盘」。这次两套合在一起写，类型留空。
- **每个知识点都要一张图，和控制成本冲突**：Skill 规定每个展开的知识点都要强尝试出图；示范要求控制数量，只出了两张，第三张按 Skill 的降级写法标「图像待生成」，成品里看得出缺一张。
- **几个小毛病**：Skill 写的启动命令会直接在用户电脑上打开浏览器，没提无界面运行时怎么办；工作台会话页的时间固定按北京时间显示，复盘文档页显示的却是写入时的本机时间，同一个复盘在两个页面上差了好几个小时；前置脚本落后远端时会自动暂存改动再拉取，多个会话共用一个仓库时有风险（这次仓库和远端一致，没触发）。
- **不适合宣传的地方**：
  - 「用户」的勾选和补充反馈都是 AI 按读者设定代填的；四句「用户原话」是示范记录里预设的说法，复盘对它们的批评是示范效果，不是真实用户的表达习惯。
  - 截图里的工作台只有一个会话，是因为特意指到了临时目录；真实使用时首页会列出全部历史复盘。
  - 复盘里提到的很多「问题」其实是各 Skill 自己的毛病，示范记录里已经写过，复盘是把它们重新归纳成给普通人的经验。
