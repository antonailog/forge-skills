# forge-eng

## 输入

- forge-dev 调度进来，设计实现已完成：分支 `eng/pomodoro-timer-2026-10-23` 上已有整页结构 `index.html` 和全部样式 `style.css`，样式文件开头写着「样式与行为的接口」（行为代码只能改哪两个属性、哪几处文字）。
- 行为契约 `.features/pomodoro-timer/feature-spec.md`（六块需求的 Given/When/Then、异常态、验收检查表）；产品 `docs/PRD.md`；设计 `docs/DESIGN.md`。
- forge-dev 本轮产物：`docs/v1.0-CONTEXT.md`（提示音现场合成、文件怎么分、用 Node 自带工具测、本地怎么预览）和 `docs/v1.0-RESEARCH.md`（推荐「纯规则文件 + 页面接线文件」两层，列了后台计时被放慢、模块脚本在本地打不开等坑）。
- 隔离副本沿用上一步建好的 `.worktrees/pomodoro-timer`。

## 用户会怎么说

「设计和样式都好了，把番茄钟的功能做出来：开始、暂停、跳过、到点提醒、刷新不丢记录。」

## 过程

0. **定位文档、选模式（第 0–0.5 步）**：找到 PRD、DESIGN、调研、视觉决策索引；项目还没有工程文档，走「创建」。功能状态文件里工程一行置为进行中。
   - 演示时由 AI 按默认确认：完整模式（forge-dev 调度进来，下游验收要用工程文档里的测试矩阵）。
1. **范围挑战（第 1 步）**：已有的只有页面结构和样式，行为要从零写；最小改动是两个脚本、一个测试文件、页面里加两行引用，远低于 Skill 的复杂度警戒线。
   - 演示时由 AI 按默认确认：接受范围，不缩减。
2. **理解现状（第 2 步）**：代码只有两个文件，直接读完，没有另派子代理扫描。回放复盘账本，挑出三条相关教训带进本次：验证命令要单独看退出码、验收工具先用已知结果验一遍、实现者自己写的测试容易把错误当成规格。
   - 演示时由 AI 按默认确认：对现状的理解无误。
3. **四章工程审查（第 3 步）**：
   - 架构：一个「纯规则」文件管所有计时、计数、文字和标题，不碰页面、不读时钟，能在 Node 里单测；一个「页面接线」文件只管存储、走秒、渲染和提醒。审查时对照 Feature Spec 找出**三种规格没写到的情形**：两个页面恢复的是同一段专注、各自到点时算几个；到点提示在刷新后还要不要保留；刚好到点那一刻按下按钮算什么。
   - 演示时由 AI 按默认确认：三处都取最简单、最不打扰用户的做法——同一段只算一个；刷新即视为看到提醒；到点优先，那一下点击不再开始休息。都写进工程文档和需求设计文档，没有加任何「非目标」里的东西。
   - 代码质量：全部页面文案只出自规则文件；页面层严格按样式接口只改属性和文字。
   - 测试：测试矩阵分三层——规则单测（自动化）、浏览器自动化（快进时钟、禁用存储、两个页面）、只能真实等待的人工项（后台到点响铃、电脑睡眠、手机锁屏）。
   - 性能：无数据库、无接口，只有后台被浏览器放慢这一个已知边界。
   - 演示时由 AI 按默认确认：四章结论全部接受。
4. **方案与工程文档（第 4–5 步）**：写 `docs/ENGINEERING.md`（模块关系图、规则口径与 Feature Spec 对照表、本机记录格式、实现清单、测试矩阵、故障模式、未纳入范围）和工程变更日志，文档入口和索引各补一行，先提交。
   - 演示时由 AI 按默认确认：架构、技术选型（不加任何依赖）、实现清单、测试矩阵照工程文档执行。
5. **隔离副本、预览、测试框架（第 5.5–5.7 步）**：沿用上一步的隔离副本，确认它被 git 忽略；项目没有统一的启动入口，预览用系统自带的 Python 在固定端口起静态服务，记下进程，用完关掉。
   - 演示时由 AI 按默认确认：沿用已有隔离副本，不新建。
   - 演示时由 AI 按默认确认：测试用 Node 自带的测试运行器，不装任何依赖（Skill 给的选项只有 vitest、pytest 和「跳过」，这一项是 forge-dev 灰区里定的）。
6. **任务拆分（第 6 步）**：拆成四个依次执行的任务——规则文件与单测（严格先写测试）、页面接线（存储、恢复、走秒、按钮、多页面）、到点提醒（提示音、点击或按键确认）、需求设计文档。功能状态文件里追加任务表，逐个更新。
   - 演示时由 AI 按默认确认：按这个拆分和测试级别执行。
7. **派给 Codex 写、Claude 验收（第 7 步，codex-delegate）**：三份代码任务各写一份任务书交给本机 Codex，三份都是一轮交回、一轮验收通过，没有返工、没有收回。每份交回后 Claude 读完整改动、亲自重跑检查、在真实浏览器里验对应的 Given/When/Then，通过后才提交，提交信息注明由 Codex 实现和作业编号。几处验收值得一提：
   - **规则文件**：除了 Codex 自己的测试全绿，Claude 还做了三件事——把实现换成「什么都没实现」的空壳，确认每组测试都会失败；把关键规则逐处改坏（去掉「同一段只算一次」、把向上取整改成向下取整、让恢复时也响铃等），确认每一处都有测试报警；另按 Feature Spec 独立写了一份检查，也全部通过。还在几个不同时区下各跑了一遍。
   - **页面接线和到点提醒**：Claude 用无头浏览器加「假时钟」把 25 分钟快进完，逐条验首次打开、开始暂停继续跳过、专注和休息到点、刷新恢复、关着页面时到点、跨零点、记录损坏、浏览器不让保存、同时开两个页面、页面隐藏后回来、手机三种屏幕、本地双击打开、到点只响一声、点击或按键停止标题交替、没点过按钮时声音被拦截也不报错。全程零控制台错误、零外部请求。
   - Claude 的验收脚本自己出过三次错（一次时间算错、两次等待时机太短），都是先查清是工具问题、修工具后再跑，没有因此去改 Codex 的代码。
   - 有一处代码写法（页面写入外面包了多余的错误捕获）Claude 先试图复现「会吞掉错误」，复现不出来，于是不返工，只记进技术债留给审查。
8. **必需产出（第 8 步）**：「未纳入范围」「已存在的内容」「故障模式」都写进工程文档；没有发现「无测试、无处理、静默失败」的严重缺口。用 forge-feature-doc 更新需求设计文档：阶段改为「已实现、待验收」，布局、六种状态、按钮细节三张图换成真实页面截图（截图脚本改为直接打开本地页面、用点按钮和快进时钟造状态），补上三条规格补齐的结论，关键改动加几行，文档检查通过。
   - 演示时由 AI 按默认确认：不新建待办文件，推迟项写进工程文档「未纳入范围」。
   - 演示时由 AI 按默认确认：到点切换阶段时主按钮换色有一下极短的过渡（设计写的是直接切换），接受现状，列进需求设计文档的待拍板，不在本步改样式。
9. **总结与收尾（第 9–10 步）**：最后在分支最新提交上重跑单测和全部浏览器场景，全部通过；关掉本地服务，确认端口释放、没有残留的 Codex、浏览器或服务进程。功能状态文件里工程一行标为已完成（状态文件由调度器统一提交）。
   - 演示时由 AI 按默认确认：分支收尾选「保留分支」——不合并、不开合并请求、不删隔离副本，这一步也不推送；推送、审查、合并交给后面的环节。

## 问题

- **测试框架选项不适合「零依赖」项目**：第 5.7 步只给 vitest、pytest、「跳过」，没有 Node 自带的测试运行器；PRD 不许加依赖时只能另选。TDD 级别也是按文件扩展名判断，普通 `.js` 不在任何一档，纯规则脚本该不该严格先写测试要人来定。
- **两套「谁来写代码」的说法并存**：第 7 步主文说「宿主是 Claude Code 时代码交给 Codex」，但它引用的 Wave 执行手册仍是「同一 wave 内用子代理并行写」，还附了一份子代理任务模板，和 codex-delegate 的任务书模板重复；提交信息格式两边也各有要求，要自己合并。
- **「文档和代码同一个提交」与「每个任务一个提交、注明由 Codex 实现」打架**：第 8 步和 forge-feature-doc 都要求需求设计文档和代码放进同一个提交，但代码是 Codex 写、按任务分别提交的，最后需求设计文档只能单独提交（文档检查按整个分支比对，所以没被拦下）。
- **步骤顺序会把工程文档写到主分支上**：第 5 步「更新工程文档」排在第 5.5 步「建隔离副本」之前，照字面执行会在主分支检出里写文档；这次隔离副本已存在才写进了功能分支。
- **确认点太多、偏重**：四章审查每章都要「停下来问」，加上方案确认、任务拆分确认、分支收尾，一个番茄钟要问用户七八次；非交互演示里全部只能代答。
- **模板以带后端的 Web 应用为准**：API 表、数据库、环境变量、查询性能占了大半，纯静态页面要整节删；「故障模式」「未纳入范围」该写在哪也没说，这次写进了工程文档。
- **端口和 APP_URL 的规矩落不了地**：Skill 要求 APP_URL「必须来自统一启动入口的状态输出，不得猜」，项目根本没有这个入口，只能自定固定端口再交给 QA。
- **小毛病**：交付总结模板里写「第0步 范围挑战」，流程里是第 1 步；Worktree 指南里还留着旧名「do-eng」；项目没有 TODOS 文件时要不要建没说。
- **和上游样式的一处偏离没在本步处理**：设计说到点时颜色「直接切换」，但样式里给按钮悬停加的颜色过渡在切换阶段时也会生效。行为代码不能写样式，只能记下来交给待拍板和后续环节。
- **codex-delegate（细节见它自己的记录）**：任务书里「等结果」的写法超过了 Claude Code 单条命令的时长上限，要分段等；Codex 的沙箱里打不开浏览器，前端验收全落在 Claude 身上；第一份任务 Codex 写测试很认真，等得比后两份久得多。
- **forge-feature-doc**：浏览器标签页标题在页面外，真实截图截不到，只能沿用设计骨架的示意图，Skill 没说「页面外元素」怎么配图；截图指南只讲「拦接口、塞假数据」，没讲这种靠时钟变化的状态怎么造；有过渡动画时截图会截到中间色（这次第一轮就截到了），踩坑清单里没有「截图前把鼠标移开、等过渡结束」。
- **不适合宣传的地方**：
  - Codex 三份任务都一次通过，是因为 Claude 在工程文档和任务书里把接口、规则口径写到了函数级别——宣传时适合讲「Claude 设计、出验收标准、亲自证伪，Codex 照图施工」，不适合讲「Codex 自己想出了架构」。
  - 最难的那条——页面在后台、人在用别的软件时到点响铃会晚多少——要真实等 25 分钟，本步没测，留给 QA。
  - 提示音只验证了「到点时确实发出了一次声音」，没有人真的听过（无头浏览器没有扬声器）。
  - 验收脚本自己错了三次，说明「自动验收」也需要人盯着工具本身。
