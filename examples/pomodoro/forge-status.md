# forge-status

## 输入

第 3 棒进行到一半时的项目仓库：

- main 上是文档和设计（PRD、需求设计文档、DESIGN.md、设计 token）。
- 功能分支 `eng/pomodoro-timer-2026-10-23` 在单独的 worktree（同一个仓库的另一份工作副本）`.worktrees/pomodoro-timer` 里，页面已经实现完。
- **另一个会话正在这个 worktree 里做 QA 验收**：本地起了一个静态网页服务，无头浏览器正在打开页面跑测试。
- 项目里没有 `.forge/active.md`（Skill 默认读的「谁在跑」登记表）。

按进度表 forge-status 排在第 5 棒；这次提前插进来跑，因为此刻正好有一个真实的并行会话可以巡检。

## 用户会怎么说

「forge 状态，看下现在谁在跑。」

## 过程

1. **找登记表**：Skill 第一步找 `.forge/active.md`，没找到，按原流程只输出一句「本项目暂无 .forge/active.md，说明还没用过并行化流程」就结束。这句话和眼前的情况相反——另一个会话正在 worktree 里干活。
2. **按 Skill 的硬信号补判**：AI 把 git 自己登记的 worktree 列表当作工作线清单，逐条套用 Skill 的两条硬信号：worktree 目录还在不在、分支有没有并进 main。
   - 照抄 Skill 里的判定命令时，「主分支叫什么」那一步取到的是空值，后面的「是否已合并」命令直接报错，这条线因此落到了「活跃」。
   - 改用正确的主分支名 main 重查：分支没有合并，worktree 也在，仍然是「活跃」。这次结论碰巧没错，但命令本身有毛病（见「问题」）。
3. **附加看一眼在跑的服务**：Skill 的固定端口清单一个都没扫到；AI 从开发调度的状态文件里找到 QA 用的网页地址，补查到静态服务和无头浏览器，它们的工作目录都在这个 worktree 里。按 Skill 规定，这些只用来让人看见「有东西在跑」，不参与活跃或僵尸的判定。
4. **清理确认**：
   - 演示时由 AI 按默认确认：选 C「先不清——只报告，不改文件」。理由：没有一条被判成僵尸，而且另一个会话正在这个 worktree 里验收，动了会打断它。
   - 「删除 worktree 目录」那一节没有触发：用户没要求删目录。
5. **全程只读**：没改 `.forge/` 下任何文件，没动 backlog，没删 worktree 和分支，没停任何进程，没提交、没推送。

## 问题

- **看不见功能开发的并行会话（最大的问题）**：「谁在跑」登记表 `.forge/active.md` 只有 forge-bugfix 领 bug 时才写；forge-dev、forge-eng、forge-qa 开 worktree 干活都不登记。所以这次另一个会话正在 worktree 里验收，Skill 按原流程第一步就退出，还说「还没用过并行化流程」。这次的巡检结果是 AI 自己改按 git 的 worktree 列表补判出来的，不是 Skill 原样能给出的。
- **判断主分支名的命令兜底失效**：Skill 写的是「从远端默认分支取名字，取不到就用 main」，但「用 main」接在了一个不会失败的文本处理命令后面，兜底永远不生效。这个仓库是本地建好再推上去的，没有记录远端默认分支，主分支名就成了空的，接下来的「是否已合并」命令直接报错，任何一条线都会落到「活跃」。
- **「是否已合并」的匹配认不出还挂在 worktree 上的分支**：git 列分支时，在别的 worktree 里检出的分支前面会带一个「+」号，Skill 的匹配规则只允许前面是空格，所以「分支已经合并、worktree 还没删」——也就是最典型的漏清理——永远判不出来，同样落到「活跃」。这一条和上一条这次没暴露，只因为这条分支确实还没合并。
- **服务巡检找不到项目自己的端口，又会混进别的项目**：固定的几个常用端口没扫到这次 QA 用的静态服务；它的地址只记在开发调度的状态文件里，Skill 不读这个文件。tmux 那一步是按名字在整台电脑上过滤，把另一个项目的会话也列了进来，对外截图前得手动删掉。
- **没有僵尸时怎么收尾没写**：交互模式固定要弹「要清理吗」的选择框，推荐项还是「全部清理」；零条僵尸时应该直接结束。另外和前面几个 Skill 一样，示范是在无界面的子任务里跑的，没有选择框工具，只能由 AI 代选。
- **报告模板按修 bug 的会话设计**：每行要填会话 id、任务编号、功能域，从 worktree 列表补判出来的工作线没有这些字段，只能换成分支名和路径。
- **不适合宣传的地方**：Skill 原样输出只有一句话，而且是错的；宣传里展示的那一屏要注明是「按 Skill 的判定规则补判」，或者等上面几处修好后重跑一次再截图。
