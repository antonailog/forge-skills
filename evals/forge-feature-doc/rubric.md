# forge-feature-doc 评分表（效果对照用）

任务：「精选筛选那块的文档太长了我看不完，帮我出一份我能看懂的需求设计文档：要能看到精选按什么规则选、关键阈值是多少、prompt 怎么判、页面上怎么展示。」
两组：用 forge-feature-doc（with）/ 不用（baseline）。都只读 info2action 仓库，不访问本地服务和数据库，所以不比页面截图。

## 客观考点（脚本或计数可判）

| # | 考点 | 判法 | 对应 skill 规则 |
|---|---|---|---|
| O1 | 待拍板放在最前面 | 标题后第一个二级标题是待拍板（或等价的「待你决定」） | 骨架第 0 部分 |
| O2 | 必有部分齐全 | 有背景、目标与成功标准、流程、细节链接、关键改动 | 按类型取舍 |
| O3 | 先图后字 | 正文图片 ≥ 4 张；各部分首个元素是图或表的比例 ≥ 60% | ADHD 写法 |
| O4 | 只写现在 | check.mjs 的历史词扫描：命中 0 | 只写现在 |
| O5 | 篇幅 | 正文（关键改动之前）中文字数 ≤ 4,000 | 篇幅预算 |
| O6 | 链接 | 文件引用都是可点的相对链接；没有坏链接 | 链接规则 |
| O7 | 关键事实覆盖 | 下列 11 个事实出现的个数（数值以代码为准） | 「放不放」判据 |

O7 的 11 个事实：
1. 举旗线 4.75（`INFO2ACTION_HIGHLIGHT_V26_THRESHOLD`）
2. 展示闸 6.5（`INFO2ACTION_HIGHLIGHTS_DISPLAY_THRESHOLD`）
3. reach 闸：reach = 1 且不是重大事件 → 不举旗
4. 硬帽：权威 = 0 或受众契合 ≤ 1 → ≤ 4.9；新颖 = 0 → ≤ 5.9
5. 五维打分 + 按内容类型的六套权重
6. 边缘带二跑：离线 ±1.0 内再跑一次，每天上限 500
7. 读模型只看近 7 天
8. GitHub 项目 ≥ 50 星
9. 没生成 why_read 不展示
10. 双评分器：生产 v26 / 备用 v38
11. prompt 版本号

## 主观考点（读完打 1–5 分）

| # | 考点 | 5 分长什么样 |
|---|---|---|
| S1 | 读完能回答四个问题 | 长什么样、按什么规则、效果由哪些数决定、还缺我哪些决定，都不用翻别的文档 |
| S2 | 设计看得见 | 漏斗、规则、展示条件画成图或表，图里有关键数字；不是装饰图 |
| S3 | 扫读友好 | 加粗开头、每条一行、段落 ≤ 3 行；扫加粗词就能定位 |
