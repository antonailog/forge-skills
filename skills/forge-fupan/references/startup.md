# 启动提问：在对话里问一次

读完会话摘要、动笔写复盘之前，在对话里发一条消息：先让用户确认「复盘的是这一次、结果是这样」，再给出知识拓展打算写什么，问他还有没有想专门学的。只问这一次，不走网页、不逐条确认。

## 格式

```
**复盘：<一句结论，和摘要标题一个意思>**（写完约要 <20–60> 分钟）

**做了**
- <阶段 1> → <阶段 2>（你定：<关键决定>）→ <阶段 3>
- <另一条线，没有就不写>

**变化**
- <之前> → **<现在，带数字>**
- <之前> → **<现在>**（<还差什么>）

**关键词**（🆕 = 以前的复盘里没出现过）
- 选型：🆕 <词> · <词> · <词>
- 效果：<词> · <词>
- 做法：<词> · <词>

**知识拓展打算写**
- ★ **<盲区标题>** —— <一句来源：你做了什么，所以补这个>
- ★ **<盲区标题>** —— <一句来源>
- <盲区标题> —— <一句来源>
- 专题：<标题> —— 你说想学「<原话>」
- 延伸：<标题> —— <为什么推荐给你>

> 回「好」就按上面写；也可以回编号删减，或说说还有想专门学的
```

- **做了**：每条线一行，阶段用 → 串，括号里带出用户当时的关键决定
- **变化**：「之前 → 现在」，结果加粗、带数字；没做到的也写，括号里说差什么
- **关键词**：按选型 / 效果 / 做法三行，🆕 排前面；🆕 用 `build.py --known-terms 词… --self <复盘文件夹> --session <会话 id>` 查，不凭印象（--session 让同一个会话以前用旧版写的复盘不算「见过」）
- **知识拓展**：盲区按影响排，★ 标前 2–3 条最值得学的；用户在会话里点名想学的列成专题；延伸 1–3 条；需求表达不用列，自动写。这里的盲区和关键词是初稿，写正文时按证据增删
- **耗时**：原话十来条、链接不多约 20 分钟；要联网核对十几个链接或会话很长的 40–60 分钟
- 数字只用会话原文里的，同一个数和后面复盘正文一种写法

## 用户怎么回

| 回复 | 怎么做 |
| --- | --- |
| 「好」「可以」「写吧」 | 按列的写，全部盲区和延伸都写 |
| 编号或标题（「只要 1、2」「不要延伸」） | 按他圈的写 |
| 说想学某样东西 | 加成一条专题学习，source 引他这句原话 |
| 纠正事实（「不是这个结果」） | 先改对，再写 |

用户启动时已经说了「直接写」「不用问」，或在非交互环境里运行（没人回复），跳过提问，按列出的全部写，在收尾汇报里说一句「按默认写了 N 条」。
