# 三、知识拓展：怎么写

按会话证据找出影响用户指挥和判断 AI 的知识盲区，主动补上；再加用户点名想学的（专题）和 AI 推荐的下一步（延伸）。补到能指挥和判断 AI 为止——说得出要什么、判断得了 AI 给的对不对、安排得了先后——不教怎么自己上手写代码。

三块共用一张知识地图，地图后面是关键术语。

## 1 盲区诊断

逐条看会话摘要里用户的原话和反应，找这六类证据：

| 证据类型 | 长什么样 |
| --- | --- |
| 问过 | 用户问「X 是什么」「为什么要 X」 |
| 没想到 | 一个该定的事用户没提，直到出问题才发现（「为什么来源都是未知」） |
| 说不出 | 用户描述了效果但叫不出名字，绕了几句话（「那种从左往右分叉的图」） |
| 判断不了 | AI 给了选项，用户按默认选或说「你定」 |
| 被动接受 | AI 解释了一个概念，用户没回应就往下走了 |
| 被纠正 | 用户说的做法被 AI 或事实纠正 |

- 颗粒度分四档：架构（整件事的结构）· 选型（用哪个方案、框架、服务）· 工具（某个工具能做什么、怎么用）· 知识点（一个概念）
- 不算盲区：用户记忆里已经有规则的；实现细节（他不需要知道的 API、库内部模块）
- 和专题重叠的（盲区正好落在用户点名想学的东西里）：写成一条专题，source 先引用户原话，再补一句会话里的证据
- 一条盲区要能挂上至少一条证据，挂不上就不写。条数不设上限，按影响排

## 2 每条知识条目

三块同一套写法，每条都要有实际内容，不能只放名词和链接：

| 字段 | 写法 |
| --- | --- |
| `source`（第一句） | 盲区：一句话说「用户做了什么，所以判断他不知道什么」，带原话或时间；专题：「你说想学什么」（引原话）；延伸：「为什么推荐给你」（这次做到哪了、下一步是什么，或对应哪个长期方向） |
| `what` 是什么 | 用这次的例子讲，或用户手上的项目举例；能用表格就用表格（「层 / 要定什么 / 这次的选择」）。读完能说出它是什么、解决什么问题 |
| `judge` 怎么判断 | 2–3 条判断标准：遇到时该选哪个、AI 给的方案哪里看对不对 |
| `say` 下次这样说 | 一句能直接复制给 AI 的指令，用上这条的关键词 |
| `verify` 怎么验收 | AI 做完后用户怎么检查：看什么、问什么、数字该满足什么关系 |
| `reading` 延伸阅读 | 1–3 个链接，每个写清是谁家的、看哪部分；每个都打开核对过 |

写法：结论先行，每段先说结论再说依据；举例优先用会话里真实发生的事和数字。

## 3 专题学习、延伸学习

- **专题**：用户口头说想学的——会话里说过的（「把这次用到的关键词都告诉我」），或启动提问时回复的。`sourceLabel: 你说想学`
- **延伸**：AI 判断适合学的，只按两条原则推荐，`sourceLabel: 为什么推荐给你`
  1. **这类工作的下一步**：地图上这次没碰到、但顺着往下就会遇到的部分（做完访问看板 → 漏斗分析、留存分析）
  2. **用户的长期方向**：工作区根 README 里有「长期方向」表就读（没有就跳过这条），挑和这次工作接得上的方向；`basis` 写「长期方向：<方向名>」
- 延伸 1–3 条，宁少勿凑；每条都要讲清「为什么现在推荐给你」

## 4 知识地图骨架（knowledge.layers）

左边是这次工作对象的结构，竖着排，4–7 层，每层写要定什么（`decide`）和这次选了什么（`chosen`）。

- 会话里定了框架就用它（例如讨论中定下的设计六步：内容 → 布局 → 视觉规范 → 交互 → 适配 → 验收）；没有就用这类东西的行业通用结构（例如访问看板是数据管道：采集 → 清洗 → 指标计算 → 定时更新 → 展示 → 访问控制）
- 每条条目挂在它落的层上（`layers`）；架构类或横跨全部层的放地图顶上；挂不上的（`layers: []`）放「结构之外」；按长期方向推荐的延伸放「往你的长期方向」
- 有盲区的层会标黄，所以 layers 要挂准

## 5 关键术语

下次开工能直接对 AI 说「用 A、B、C 做 X」，让它一开始就走对方向。

- **只收有指向性的词**：不说这个词，AI 可能走到另一条路上的词。判据：「不说它，AI 会不会做出别的选择？」会 → 收。实现细节（具体 API、库内部模块、状态码、函数名）不收，那是 AI 实现时自己选的；项目内部名字（脚本名、路径、IP）和太泛的词（「代码」「优化」）不收
- **一级按这次碰到的领域分模块**，外加一个「工作方法」，每块 3–5 个词。`area` 是领域的通用叫法（前端、数据、部署、设计、写作……），`name` 是这块在这次工作里叫什么（看板页面、访问统计）。块内三类：
  - **选型**：本次选的框架、方案、服务，加 1–2 个主要竞品，各写一句适合什么（React，竞品 Vue）
  - **效果**：想要的结果怎么叫（桑基图、互动用户口径）
  - **做法**：流程和验收怎么叫（先写追踪方案、上线前代码评审）
- **每个词写**：`what` 一句「能做到什么 / 适合什么」，不写百科定义，15–30 字；`side`：mine 这次最终用的 · talked 会话里出现过但最终没用（讨论过、试过又换掉）· base 会话里没出现、业内常用的；外部链接（`src`）；在路线图哪一步出现（`step`）；对应哪条知识条目（`kref`）；图标（`icon`，品牌词用品牌标）
- **第一次见**：把这次的词一次性交给 `build.py --known-terms 词1 词2… --self <复盘文件夹> --session <会话 id>`，输出「第一次见」的标 `new: true`
- **每个模块写**：一句「下次这样说」，把这块的词串成一句指令
- 对标分析里各步的关键词，挑影响方向的汇总进来，每块仍保持 3–5 个；同一个词只出现一次

## 写完自查

- 每条盲区的 source 里有证据（原话、时间或行为），不是「你可能不了解」
- 每条的 say 和 verify 都能直接用，不是「注意 X」这类空话
- 每个外链都打开过；关键术语里没有函数名、状态码、路径
