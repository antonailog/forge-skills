# forge-fupan — 单篇复盘与复盘汇总

产出一份单篇复盘：一个能双击打开的阅读页，三节——工作总结、工作复盘、知识拓展，归进 `记录/复盘/<项目>/<模块>/`，并刷新工作台（复盘汇总、经验、知识三页）；认领的经验和知识编号写进经验库、知识库。

写复盘默认交给执行方（Codex），用户正在对话的会话只做调度：转启动提问、验收、收尾。

## 立场

像一个跟完全程的资深同事，收工后给用户做一次 code review 加一对一辅导。只拿会话里的证据说话，先给结论：这次做成了什么、和业内最佳路径差在哪、哪句话没说清、哪一步是 AI 替他默认的；再把他下次指挥 AI 需要的那点知识补上——补到能说出要什么、能判断 AI 给的对不对就停，不教他自己上手写。

复盘是给用户复习用的材料，读完当场看一遍，之后按项目、模块回来翻。所以它不写进记忆、不写教训账本，也不替用户改任何规则文件。经验库、知识库跟着复盘长：你在 JSON 里写认领和编号，build.py 按它们往库里写这篇，库里的文件你不直接改。

## 按需读取

| 文件 | 什么时候读 |
| --- | --- |
| `references/dispatch.md` | 用户说「复盘」后最先读：选执行方、写任务书、转话、验收（你是被派来的执行方就不用读） |
| `references/startup.md`、`references/write-knowledge.md` | 第 3 步发启动提问之前（启动消息要列盲区和关键词，判定标准在 write-knowledge.md） |
| `references/write-overview.md` | 第 4 步写一、工作总结之前 |
| `references/write-review.md` | 第 5 步写二、工作复盘之前 |
| `references/write-knowledge.md` | 第 6 步写三、知识拓展时回来对照 |
| `references/schema.md` | 写第一份 JSON 之前；build.py 报字段错时回来查 |

脚本都在 `scripts/`，`SKILL_DIR` 是本文件所在目录（通常 `~/.claude/skills/forge-fupan`）。

## 流程

**0 派活**：按 `references/dispatch.md` 选执行方、写任务书派出去。执行方做第 1–7 步，第 3 步写好启动消息就停下交回；调度方把它原样转给用户，再把回复转回去，最后做第 8、9 步并验收。你是执行方，或宿主本身就是 Codex，就从第 1 步做起。

**1 找会话**

```bash
python3 $SKILL_DIR/scripts/find_session.py            # 当前会话
python3 $SKILL_DIR/scripts/find_session.py --grep 关键词   # 复盘过去的某次
```

用户说「复盘刚才那个」「复盘 X 那次」时用 `--grep` 或 `--list` 找；拿不准是哪一份，列出候选让用户挑。

**2 压成摘要**

```bash
python3 $SKILL_DIR/scripts/digest.py <jsonl> -o <临时目录>/digest-<会话 id 前 8 位>.md [--until '11-04 12:15']
```

只读摘要，不直接读几十 MB 的 JSONL。摘要里有用户原话（U1、U2…，北京时间）、AI 每步做了什么、写过的文件清单。AI 回复是截断的，要看全段加 `--text 2000` 重出，或回 JSONL 里 grep。同时看一眼 `git status` 和最近的提交，用来判断摘要状态和遗留事项。

**复盘范围**：从这件事开始，到用户要求复盘之前。会话末尾如果已经做过一次复盘、或者夹着别的不相干的事，用 `--from` / `--until` 切掉，文件清单里那段写的文件也不算。

**3 启动提问**：按 `references/startup.md` 在对话里发一条，等用户回（执行方：写进 `_启动消息.md`，最后一条消息只放它，然后停下）。这一步要先粗定关键词和盲区清单（初稿，写正文时可以调整）。用户说过「直接写」或没人回复（非交互运行）就按默认写。

**4 写一、工作总结** → `1-总结.json`、`2-交付物.json`（规则 `write-overview.md`）。摘要最后写。

**5 写二、工作复盘** → `3-复盘.json`（规则 `write-review.md`）：先列这类活的业内做法和你自己的判断，再联网核对。对标分析写完，用 `build.py --catalog` 看经验库，这次做的事对应哪份经验就认领（`review.sops`，写法见 write-review.md「认领经验」）；对不上的记进 `review.sopCandidates`。

**6 写三、知识拓展** → `4-知识.json`（规则 `write-knowledge.md`）。每条知识条目、每个关键术语对照 `build.py --catalog` 的知识库标编号（`kb`），库里没有的条目写 `null`。知识条目多于 3 条时可以派子 agent 并行写，每个写一份 `4-知识-<id>.json`；给它会话摘要路径、这条的盲区证据、write-knowledge.md 和 `build.py --catalog` 输出的知识库那段，只让它写条目（含 kb）、核对链接，不让它报数字——数字以你从会话里核对的为准。

**7 出页面**

```bash
python3 $SKILL_DIR/scripts/build.py <复盘根>/<项目>/<模块>/<日期>-<标题>/    # 复盘根默认 ~/claudecode_workspace/记录/复盘，别的环境先设 FUPAN_ROOT
```

它校验字段和互相引用、读文件内容、按函数名算行号、打码、截图，写出 `data.js` 和「打开复盘.html」，再重建汇总页。有经验库、知识库时，认领的经验和知识编号同时写进去：经验底部加这篇、认领的步骤换成这次的一句；知识点加出处；对不上的进经验候选、知识待归位。同一篇重跑等于覆盖：上次写进库的先撤掉、被换掉的句子还原，再按这次的写（记录在库根的 `复盘写入记录.json`）。只撤得掉 build.py 写进去的，迁移进库的不算；复盘文件夹删掉或改名，写进去的不会自动撤，重建汇总页时会提醒。报错就按提示改 JSON 重跑，别手改生成的文件。同一个会话再复盘，沿用原来的文件夹名、覆盖里面的 JSON（换了标题也别新建文件夹）。文件夹名里不能有 `# ? % &`。

**8 自查**：打开「打开复盘.html」看一遍（有 Playwright 就截首屏看），确认三节都在、链接能点、抽屉能打开。执行方写的，第 8 步由调度方按 dispatch.md D5 做，并用 `scripts/check_quotes.py` 查原话。

**9 收尾**
- 如果项目根有 `.forge/active.md`，删掉当前这个会话（正在跑复盘的会话）登记的那一行（forge-bugfix 把这件事交给复盘做）
- 回复用户：复盘页地址 + 三行——结果、最值得看的一条对标、补了几条盲区；按默认写的说一句
- 复盘页地址用 build.py 最后打印的「浏览器地址」（`file://…/index.html#r=<项目>/<模块>/<文件夹>`），放进代码块，请用户粘进浏览器地址栏。不给「打开复盘.html」的相对链接：在 VS Code 这类编辑器里点它会在编辑器里打开，不执行跳转，落不到这一篇

## 产出

```
记录/复盘/
├── index.html                 工作台：顶上切换复盘 / 经验 / 知识；复盘默认「最近」跨项目按月倒序，点项目看各模块现状和时间线
├── index.data.js
├── 经验.data.js、知识.data.js   经验、知识两页的数据，从经验库、知识库生成
└── <项目>/<模块>/<YYYY-MM-DD>-<标题>/
    ├── 1-总结.json … 4-知识.json    复盘真源，你写的
    ├── data.js                    build.py 编出来的（含文件内容快照）
    ├── shots/                     截图
    └── 打开复盘.html               双击打开，跳到汇总页里这一篇
```

经验库、知识库默认在复盘根上两级的 `知识/知识图谱/2-结果区/`（`经验库/`、`知识库/`；复盘根用默认值时就是 `~/claudecode_workspace/知识/知识图谱/2-结果区/`），别的位置设 `FUPAN_KB`。`build.py --catalog` 说没有，就不写认领和编号，工作台只有复盘页能看。

`记录/复盘/` 下以前按时间写的 md 复盘不动；它们的模块、项目显示名和两行描述写在 `记录/复盘/旧复盘描述.json`，汇总页读它，没写到的放「未分模块」。标题文件夹名用 `<日期>-<摘要标题的短版>`，不超过 20 字。

## 红线

1. **证据只取会话原文**。数字、原话、验收结果照抄会话里的，不估算、不补全；同一个数全篇一种写法。复盘是用户以后回来查的依据，一个编出来的数会让整篇都不可信。
2. **外部链接打开核对后才写**：能打开，引用的那句话原文里有。用户会照着链接去学，死链和张冠李戴比没有链接更糟。
3. **页面上不出现账号、密码、令牌、IP、私人邮箱**（发信用的 noreply 地址除外）。要登录的写「需密码」；原话里带了邮箱、IP 的，那一段换成「‹邮箱›」「‹IP›」。build.py 会拦住文字里的 IP 和邮箱，文件内容里的会自动打码；登录用的账号名、私人微信号这类它认不出，写进 `mask`；用户自己公开的网站域名、品牌名、社交主页不算隐私，不打码。截图打不了码，画面里有就不放截图。
4. **不写记忆、不写 learnings.jsonl、不改旧复盘**。复盘是复习材料；记忆和规则文件由用户自己决定改不改，旧复盘用户定了原样保留。

## 出问题时

| 情况 | 怎么办 |
| --- | --- |
| Codex 派不出去、没装 codex-delegate、启动卡死两次 | 换 Claude 子 agent，任务书不变（dispatch.md） |
| 执行方返工两轮还不过 | 换另一个执行方，用接手版任务书只重写出问题的那几份 JSON（dispatch.md D5） |
| 找不到会话日志 | 用当前上下文或现成的过程记录写，摘要的 got 里注明「会话日志缺失」；过程回顾只写能确认的；拿不到用户原话就不写需求表达，不凭记忆复述 |
| 会话被压缩过 | JSONL 里原始消息还在，照常用 digest.py |
| 截图失败、页面要登录 | 不截，结果卡只放链接，写「需密码」 |
| 链接打不开或找不到原话 | 换一个来源；找不到可靠来源的词不挂链接 |
| 这类活没有公认流程 | 对标分析不画路线，挑 3–5 个关键做法对照（write-review.md 有写法） |
| 用户只想重建汇总页 | `build.py --index`（顺带重建经验、知识两页的数据） |
| 认领的经验、知识编号对不上 | `build.py --catalog` 看全部编号；库里确实没有的，经验写进 sopCandidates，知识条目 kb 写 null |
| 阅读页本身要改（样式、组件） | 源码在仓库 `tools/fupan-reader/`，改完 `npm run release` 会更新 `assets/reader.html`；不在 skill 里改生成的 html |
