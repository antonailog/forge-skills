# forge-status

同时开好几个 AI 会话时，查进度、清残留

## 要解决的问题

多个窗口并行修 bug 时，每个会话在 `.forge/active.md` 登记自己占用的 worktree 和功能域，正常收尾由复盘清掉。但会话会崩、人会漏复盘、worktree 会被手动删，登记就成了「僵尸」，新会话据此判重时，会以为那块还有人在修。按「超过 N 小时没动静」来清，又会误杀只是 AI 跑得慢、或人离开几小时还会回来的会话。连 worktree 目录一起删时，里面没提交的文件也可能跟着丢。

## 运行方式

![forge-status 结构图](../../docs/diagrams/forge-status.jpg)

逐条读 active.md 的登记，每条只查两件事：worktree 目录还在不在、分支合没合进 main；目录还在、分支也没合并，才算活跃。用户直接调用时，报告后问一次：全清、逐条看，还是先不清；清记录时同步改 backlog 里对应 bug 的状态。forge-bugfix 开工时调用它，只报数，不改文件；用户明说要删 worktree 目录时，另走「列清单确认 → 停服务 → 备份并核对文件数 → 删除」，哪一步不通过就停。

## 关键设计

一次巡检要同时做到两件事：清掉没人用的登记，保住还在干活的会话。forge-status 分判定、报告、清理三段：判定只认能直接查证的硬信号，报告把活跃和疑似僵尸分组列出，清理默认只改登记表和 backlog 两份记录。

- **判僵尸只认能直接查证的硬信号**：worktree 目录不存在算已弃用，分支已合并进主分支算已完成，两条都不满足就算活跃。判定只看这两件事，AI 跑得慢、会话进程已经退出，登记都照常保留（`SKILL.md`）。
- **服务巡检只负责让用户看见**：附带列出 .devserver.json、tmux 会话和监听端口上进程的 PID 与 cwd，帮用户发现多余的前后端；这部分在报告里单独成段，并注明它只说明有服务在跑，判定结果照旧只看两个硬信号。要停服务，就提示用户在对应 worktree 里跑项目自己的停止命令（`SKILL.md`）。
- **登记和 backlog 一起改**：从 active.md 删掉一条后，已合并的任务在 backlog 里改为 resolved、移到「已处理」对应月份；worktree 没了、分支也没合并的改回 pending。两种都清空「领取会话」，没做完的下次可以重新领（`SKILL.md`）。
- **删 worktree 目录先备份、再核对**：默认只编辑 active.md 和 backlog.md。用户明说要删目录时，先按「可直接删、备份后删目录保留分支、不动」三类列清单请用户确认，停掉目录里的服务，再把未跟踪和被忽略的文件打包、核对文件数，对不上就停；有独有提交的分支保留，备份目录里写明怎么恢复（`SKILL.md`）。

```text
forge-status/
└── SKILL.md   硬信号判定、分组报告、联动清理、删目录流程
```

## 其他

- 前提：项目里有 `.forge/active.md`，没有就直接退出，说明还没用过并行流程；目前只有 forge-bugfix 会往里登记
- 注意：「全部清理」只在明确选它时执行，回复含糊就按逐条确认处理
- 注意：只说「清理 worktree」时只清登记；要删目录得明说「删掉没用的 worktree」或「清理 worktree 目录」
- 注意：dev server 巡检扫的是常见端口，项目自定义端口以项目 CLAUDE.md 或 `dev:status` 为准
