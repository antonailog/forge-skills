# forge-brainstorm

头脑风暴：先挑战前提，再给 2—3 个方案

## 要解决的问题

想法还没想清楚就开始写需求，AI 往往顺着用户说「好主意」，照字面往下做，最后解决的可能是个错的问题。Forge 的前身以写 PRD 为流程入口，中间没有讨论这一步。聊出来的结论只留在对话里，换个会话或换台电脑就接不上。

## 运行方式

![forge-brainstorm 结构图](../../docs/diagrams/forge-brainstorm.jpg)

产品、内容、构建、探索四种模式共用一条流程，差别在问哪套题、要不要搜外部现状、最后推荐去哪（见图下表）。用户拍板三次：确认模式、选方案、定下一步；不想再被问时说一句「别问了」，直接出方案。

## 关键设计

- **出方案之前先挑战前提**：必问「这是正确的问题吗、不做会怎样、已有什么能复用」，问题错了，方案再好也白做
- **不许只给一个方案，推荐要引用用户的话**：至少两个，各写「不做什么」和缺点；推荐写「因为你说了 X」，不写「综合考虑」
- **思考文档先过一个怀疑论者**：派独立 subagent 找最容易失败的点、最大盲区、资源减半时砍什么，附在文末再交用户确认
- **决策表只追加，AI 不代填「答：」**：新一轮审视另起一节，不回改上一轮，决策怎么走过来的能复盘，下次也能接着聊
- **产品模式不许跳过 PRD**：Feature Spec 的验收场景要在开发前定好；构建模式做小 demo 可以直接进 forge-dev

## 其他

- 前提：景观感知要用 WebSearch；画图辅助用 Mermaid 或生图工具，没有生图工具时只保存 prompt，不假装已经生成
- 注意：思考文档是原始讨论，默认归档；用户确认后的结论才写进项目的当前文档
