# forge-eng

工程实现：worktree 隔离、分级 TDD

## 要解决的问题

让 AI 直接写代码，常见三个问题：还没跑验证就说「已修复」；先写实现再补测试，补的测试一跑就过，证明不了什么；多个会话在同一个目录改代码，互相冲突，开发服务抢端口，浏览器里看到的是旧代码。

## 运行方式

![forge-eng 结构图](../../docs/diagrams/forge-eng.jpg)

有 PRD 和 ENGINEERING.md 时默认走完整模式；小 demo 可选轻量模式，跳过文档和审查，worktree、TDD、验证门和原子提交照样保留。完整模式下四章审查每章停一次问用户，方案经用户拍板才建 worktree 开工。每个原子任务过了验证门才提交，修 3 次不过就停下报告；最后由用户选合并、提 PR、保留还是丢弃分支。

## 关键设计

- **不验证不准说完成**：提交前跑验证命令、读完整输出、看 exit code，禁用「应该可以」「可能修好了」；AI 有还没验证就宣布完成的倾向
- **TDD 按任务分级**：后端逻辑和 bug 修复先写失败测试，先写了实现就删掉重来；前端组件补关键交互测试，样式和配置跳过，全量 TDD 不适合大量 UI 工作
- **同一问题修 3 次不过就停**：不试第 4 次，回头和用户讨论设计是不是有根本问题
- **完整方案只多几分钟，就做完整的**：AI 辅助下做完整的边际成本接近零；范围另用硬阈值卡住，超过 8 个文件或 2 个新类/服务就建议缩减
- **每个会话一个 worktree**：不在主工作目录写代码，多会话互不冲突；开发服务走项目统一入口，测试地址从状态输出读，不猜端口
