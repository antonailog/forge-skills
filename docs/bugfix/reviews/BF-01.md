# BF-01 划线虚线在横向滚动容器里指错位置

## 来源与现象

- 来源：用户 2026-11-11 上线后实测，截图在作者工作区 `工具/复盘改造/1-工作区/07-划线回顾/2026-11-11-截图-BF01虚线指错.png`（含个人页面内容，不进公开仓库）（「线没有指向对应位置」）
- 现象：复盘单篇「关键决策」表格横向滚到右边后，划在「决策」列（已滚出可见区）的一条 ❓，右侧卡片正常，虚线却从页面最左边出发、横穿整行
- 关联 Feature Spec：`.features/fupan-highlight/feature-spec.md` 组件清单「右侧批注栏（A 样式）」→ 虚线「从原句末尾在行间空白里走到卡片」

## 复现（线上 http://127.0.0.1:4330，只读）

页面 `#r=forge-skills/复盘工具/2026-11-11-经验与工作台上线`，划线原句「品牌名定为 Learn With AI，字标选 H9 手写方案」：

| 状态 | 原句矩形 x | 表格可见区 x | 虚线起点 |
| --- | --- | --- | --- |
| 表格未滚动 | 367–688 | 289–1159 | 690（正确） |
| 表格滚到最右（scrollLeft 915） | −548–−227 | 289–1159 | −225（画在看不见的地方） |

## 根因（5 Whys）

1. 虚线为什么从页面最左边出发？起点 endX = −225，在屏幕外
2. 为什么在屏幕外？原句在「关键决策」表格的横向滚动容器里，滚走后它的排版位置在容器可见区左边外面
3. 为什么用了看不见的位置？`Annotator.tsx` 的 `measure()` 直接用 `range.getClientRects()`，它返回排版位置，不管祖先容器的 overflow 裁切
4. 为什么没处理？样稿和 Feature Spec 只考虑了正文流里的文字，没考虑可横向滚动的区域（关键决策表、对标路线横滑、代码块、宽表格）
5. 为什么测试没抓到？浏览器自测划的句子都不在滚动容器里

## 修复方案（用户 11-11 选「看不见就不画线」）

- 原句矩形与从原句到正文根之间所有 overflow 非 visible 的祖先的可见区求交，只用看得见的部分
- 部分可见：虚线从可见部分的末尾出发
- 完全看不见：不画虚线，卡片照常（与那一行对齐）
- 正文里任何容器滚动时重新计算位置（滚回去、原句露出来，虚线就出现）

## TDD 证据

浏览器自测（Playwright，临时数据、假 CLI）新加第 28 步 `28-scroll-clip`：在横向滚动容器里划一句，断言未滚动时虚线起点贴原句末尾、滚到原句完全看不见时没有虚线而卡片在、部分可见时起点在容器可见区内、滚回后虚线回来。
