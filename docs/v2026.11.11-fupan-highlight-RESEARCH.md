# 技术调研报告 — v2026.11.11-fupan-highlight

## 调研时间：2026-11-11
## 调研范围：工作台划线批注、已读、本地服务、飞书间隔推送

### 一、技术方案推荐

- 原文上色：CSS Custom Highlight API（`CSS.highlights` + `::highlight()`），不改 React 管的 DOM。Chrome 105+、Safari 17.2+、Firefox 140+。`::highlight` 规则 Tailwind 4 的 CSS 处理器不认（构建报 warning），样稿改成组件里输出 `<style>`
- 原句定位：W3C Web Annotation 的 TextQuoteSelector，库用 `@apache-annotator/dom@0.2.0`。坑：包里漏写 `@apache-annotator/selector` 依赖要手动装；`optimal-select` 入口写错，vite 里 alias 到空模块（样稿 `vite.config.ts` 已处理）
- 服务：Python 标准库 `http.server.ThreadingHTTPServer`，只绑 127.0.0.1；JSON 文件存储，写入用临时文件 + `os.replace`，并发用 `fcntl.flock`（serve.py 和 push.py 共用同一把锁文件）
- 生成：本机 Claude CLI 非交互（`-p`，stdin 接 /dev/null，限时 120 秒），输出要求 JSON；单线程队列
- 推送：飞书开放平台 `im/v1/messages`（receive_id_type=chat_id，msg_type=interactive，卡片 schema 2.0：column_set background_style grey-50、markdown text_size heading 已实测可用）
- 定时：LaunchAgent，服务 `KeepAlive`；推送 `StartInterval 600`，脚本里按 `Asia/Shanghai` 判断（系统时区是洛杉矶，`StartCalendarInterval` 会跟着夏令时跑偏）

### 二、架构模式推荐

- 页面 ↔ 服务：REST JSON；页面先 `GET /api/health`，不通就整套划线和已读不渲染（file:// 也是这条路）
- 划线存「快照」（block + quote + doc + section），推送只读快照，原文以后怎么改都不影响
- 生成和推送解耦：服务负责生成并存回，推送脚本只拼卡片和记 `pushes`；推送前对 failed 的再触发一次，仍失败用拼接背景

### 三、风险与坑点

1. **静态资源跨域偷读**：本地服务托管的 `index.data.js` 是 `window.__FUPAN__ = …` 脚本，任意网站都能 `<script src="http://127.0.0.1:4330/…">` 读到全部复盘。规避：按 Fetch Metadata 资源隔离策略，`Sec-Fetch-Site` 为 `cross-site` 的请求一律 403；校验 `Host` 为 `127.0.0.1:4330` 或 `localhost:4330`（防 DNS 重绑定）
2. **跨站写接口**：写接口要求自定义请求头 `X-Fupan: 1`（迫使跨站请求走 CORS 预检，服务不回 CORS 头即被拒），并拒绝 cross-site
3. **相对路径断**：经验图片是 `../../知识/知识图谱/2-结果区/经验库/图/`；服务托管工作区根并只放行两棵目录可解决；旧复盘有 1 篇引用复盘根外的图，http 下显示不出（可接受，记入 QA）
4. **旧复盘地址**：`ReviewIndex.oldHref` 在没有 `rel` 时用 `location.pathname` 推复盘根；http 下根路径变了，要确认 index.data.js 里 200 条旧复盘都有 `rel`（现有 200 个 rel 字段）
5. **launchd 环境**：没有 shell 别名和交互式 PATH；Claude CLI 走的代理在 `~/.claude/settings.json` 的 env 里，CLI 自己会读；飞书接口国内直连
6. **端口**：已用 4310、4311、4320、4371；4330 空闲，被占时启动失败、写日志，不自动换
7. **原文重写**：经验每步的历史相关会换成最近一次、知识点会批量重写 → 页面上找不到原句的划线不出卡片，数据和推送不受影响
8. **build.py 扫目录**：根目录下 `_` 开头的目录已被跳过（build.py 第 870 行），`_划线/` 不会被当成项目
