# PRD 变更日志

## [v2026.11.11-fupan-highlight] - 2026-11-11

### 变更背景

工作台（复盘 / 经验 / 知识）只能读。读的时候冒出的三种反应——卡住、被点亮、想照着跟 AI 说——当场就没了；记在浏览器里 AI 读不到，也没有「下次」回来看的时刻。

### 用户原始需求

「我想给它做成一个常驻本地服务，支持我进行一些简单交互：看到不懂的划线留一个 todo；看到高质量的知识（可能是一句、可能是一段），收藏下来，下次再看看；看到好的和AI沟通的表达，划线收藏下来」；双向钢人后：「我希望划线之后，我能持续巩固、学习，你可以通过飞书消息的方式给我发送到某一个频道」；之后补「还要增加一个「复盘」「经验」内容的已读未读功能」，再改为「每一篇文章详情最下方增加一个已读按钮，点击后，列表中这一条置灰」。

### 设计方案

划线（⭐ / ❓）+ 右侧 A 批注栏 → 本地服务存文件、后台生成背景和讲解 → 作者工作区推送脚本按 3 次节奏发飞书群；文章底部已读按钮、列表置灰。

### 关键决策

| 议题 | 决定 | 原因 |
| --- | --- | --- |
| 划线类型 | ⭐ 收藏、❓ 不懂两种 | 用户定，好知识和好表达都算收藏 |
| 右侧样式 | A 批注栏 + 虚线 | 三种样稿里用户选 A |
| 推送频道 | 飞书群 Learn With AI | 用户每天会看飞书，推送替他定了回来看的时刻 |
| 推送节奏 | 当晚 21:00、次日 09:00、第三天 09:00，共 3 次 | 用户定「先 3 次，不然太多」「当晚、第二天、第三天」 |
| 卡片结构 | 每条灰底一块：背景 / 疑问·收藏 / 备注；背景先写项目和在做的事；模块名加粗、无表情 | 用户嫌没背景读起来不知所云、层级不对 |
| 背景写法 | AI 按划线所在那一块原文写白话（T2），存回、三次同一份 | 三种写法里用户选 T2 |
| 讲解时机 | 划完就生成，页面卡片下可见 | 用户选「划完就出」，不懂的时候最想马上懂 |
| 已读 | 详情底部按钮 + 列表置灰；不记读到哪 | 用户嫌圆点、进度、百分比太吵，改为按钮 |
| 历史复盘 | 全部算未读 | 用户定 |
| 代码位置 | 页面和服务进 skill，推送和凭证在作者工作区 | 公开仓库不能放飞书凭证；别人装 skill 也能划线 |
| 知识点旧收藏 | 去掉 | 和 ⭐ 收藏重名、意思不同 |

### 影响范围

- 新增：`scripts/serve.py`、`tools/fupan-reader/src/annot/`、`.features/fupan-highlight/`
- 修改：阅读页单篇、旧复盘、经验详情、知识点弹窗、汇总页、经验首页；`scripts/build.py` 打印地址；README、SKILL 的打开方式
- 删除：`tools/fupan-reader/src/kb/favs.ts` 和知识页的收藏入口

## [v2026.04.27-fupan-report-structure] - 2026-04-27

### 变更背景

用户反馈最终复盘的仪表盘、会话脉络、决策复盘、避坑指南、效率词典和下次行动清单阅读价值低，Prompt 分析也需要减少批改感，转向表达优化、行为诊断和知识学习。

### 需求调整

- 删除最终复盘中的“仪表盘速览”和“会话脉络”。
- “工作叙事”改为短段落叙事，不再输出阶段列表、token 图或精力分布。
- “逐条 Prompt 分析”删除严重度标记，只保留“表达问题”和“低关键词版 / 进阶版”的更好说法。
- “模式诊断”改为“行为诊断”，用“问题 / 分析 / 建议”说明跨 prompt 的协作行为问题。
- “知识拓展”按单个知识点展开，每个知识点固定为“是什么 / 怎么用 / 延伸学习”。
- 每个展开知识模块默认强尝试生成 1 张 Image 2 学习图，作为知识地图记忆辅助；失败时保留 prompt pack 并明确标注待生成。
- 最终回复必须报告学习图状态：已生成 N 张 / 待生成 N 张，避免把占位误报为完成图片。
- `延伸学习` 至少给出 1 个权威来源链接，按官方/主流项目文档优先，不要求每类资源都齐全。
- Workbench `selection.feedback` 必须进入调研和最终输出，不能只存储不消费。
- 会话读取必须兼容 Claude Code 和 Codex Desktop，Codex 环境优先通过 `CODEX_THREAD_ID` 定位当前 JSONL。
- 上下文压缩后必须先检查本地 JSONL 原始消息可用性；可恢复则完整复盘，不可恢复则轻量复盘并禁止伪造逐条 Prompt 证据。
- 删除独立“决策复盘”“避坑指南”“效率词典”“下次行动清单”。
- “AI 表现复盘”不再固定四个维度，由 AI 根据会话证据自行诊断表现问题。
- TLDR 放在全文最后，聚焦需要记住的知识、表达优化和协作 SOP。

### 影响范围

- `docs/PRD.md`
- `docs/DESIGN.md`
- `docs/ENGINEERING.md`
- `skills/forge-fupan/SKILL.md`
- `skills/forge-fupan/parse_tokens.py`

## [v2026.04.25-fupan-workbench-polish] - 2026-04-25

### 变更背景

用户在真实使用 Fupan Workbench 后反馈：首页时间不是中国上海时区语义、已经完成复盘的任务仍然停留在顶部队列、“表达待优化原话”字号太小、历史复盘详情页缺少可点击目录，整体阅读和导航仍有摩擦。

### 需求调整

- 首页任务和历史时间以中国上海时区展示。
- `consumed` task 视为已完成复盘，必须从首页任务队列出队。
- 没有待处理任务时，首页直接展示历史复盘，不展示空任务面板。
- “表达待优化原话”作为关键学习材料，正文不小于 17px，问题/建议说明不小于 14px。
- 历史复盘详情页为 H2/H3 生成目录和锚点，支持点击跳转。
- `forge-fupan` 在最终复盘生成后应标记对应 task 为 `consumed`。
- Markdown 图片支持点击放大查看，方便检查仪表盘、流程图和截图细节。
- 左侧“学到的知识”必须是编号学习地图，展示知识点数量，不再使用大面积蓝色标签堆叠。
- 每篇最终复盘 Markdown 必须在全文最后增加 `TLDR`，用 5 条以上短分点提炼知识、表达优化和协作 SOP。

### 影响范围

- `docs/PRD.md`
- `docs/DESIGN.md`
- `docs/ENGINEERING.md`
- `skills/forge-fupan/SKILL.md`
- `skills/forge-fupan/workbench/`

## [v2026.04.24-fupan-workbench] - 2026-04-24

### 变更背景

用户反馈现有 `forge-fupan` 复盘文档虽然信息充足，但阅读成本高、专业名词密集、Prompt 诊断有批改感，且复盘前没有询问用户想学习哪些知识、学到什么程度。用户进一步提出希望把 `forge-fupan` 做成本地 localhost 页面：在复盘启动后通过前端完成知识点选择、学习深度选择和反馈提交，最终同时保存 Markdown 和网页阅读版本，历史复盘也能按项目浏览。

### 用户原始需求

用户确认的关键需求：

- 数量和深度都希望由用户选择。
- 触发 `forge-fupan` 后自动打开浏览器页面。
- 尽量在前端页面完成交互、查看结果，不要求用户回命令行。
- 学习深度分为三档：了解、表达、复现。
- 前端减少切换，一个首页分区展示当前待确认任务和历史复盘，点击后进入详情页。
- 所有前端设计环节都要用 Image 2 先生成视觉稿给用户确认。
- 历史复盘模块不显示 “My selections” 或旧选择过程，只显示最终学到了什么。
- 可能同时存在多个复盘任务：首页需要有任务队列，但一次只展开一个任务；AI 只轮询自己创建的 task ID。
- 技术路线倾向 React + FastAPI，但要求轻量、本地、只有用户自己看。
- 功能应直接进入 `forge-cookbook`，让所有使用 Forge Skill 的人都能用。

### 设计方案

新增 Feature Spec：**Fupan Workbench 本地交互式复盘学习工作台**。

核心方案：

1. `forge-fupan` 启动后先分析会话并生成学习地图草案。
2. 系统创建本地 task JSON，状态为 `pending_selection`。
3. 启动或复用绑定 `127.0.0.1` 的 FastAPI 服务。
4. 自动打开浏览器到 React 工作台首页。
5. 用户在页面选择知识点、学习深度和补充反馈。
6. 页面提交后 task 变为 `submitted`。
7. AI 轮询 task 状态，检测提交后自动继续调研和生成复盘。
8. 最终保存 Markdown，并在网页中展示历史复盘和详情页。

### 关键决策

| 议题 | 决定 | 原因 |
|---|---|---|
| 是否做独立产品 | 不做，作为 `forge-fupan` 内置 workbench | 降低范围，直接服务 Forge 复盘流程 |
| 是否所有交互都在前端 | 第一版尽量前端闭环，AI 通过轮询 task 状态继续 | 避免用户提交后还要回命令行说“好了” |
| 学习深度 | 使用 `了解 / 表达 / 复现` 三档 | 更贴近用户学习目标，比四档更清楚 |
| 前端设计确认 | 所有前端设计使用 Image 2 生成视觉稿 | 用户先看效果，减少纯文字设计误差 |
| 历史列表字段 | 只显示学到的知识，不显示 My selections | 用户回看时关心学习成果，不关心当时选择过程 |
| 多任务并存 | 任务队列 + 单任务展开，AI 只消费自己的 task | 防止多个复盘表单堆叠，也避免跨会话误消费 |
| 前端页面数 | 首页工作台 + 详情页 | 首页减少切换，详情页保证阅读体验 |
| 技术路线 | FastAPI + React/Vite 预构建静态前端 + JSON/Markdown | 兼顾交互体验和 Skill 分发 |
| 存储 | 不引入数据库 | 第一版只需本地文件，避免迁移和维护成本 |
| 访问范围 | 只绑定 `127.0.0.1` | 只有本机用户可看，避免外网暴露 |
| 超时策略 | 默认等待 30 分钟 | 防止 AI 无限等待 |
| 失败降级 | 服务失败时降级到对话内确认 | 保证复盘流程不被 workbench 阻断 |

### 影响范围

  - `docs/PRD.md`
