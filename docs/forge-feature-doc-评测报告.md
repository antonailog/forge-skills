- **用 skill（第一轮）**：按 SKILL.md 执行，写进一个空目录（不在仓库里），产出 6 张图。

### 3.2 主观考点：三位盲评（第一轮 vs 不用 skill）

三个独立子代理，各读两份文档和全部图片后按 rubric 打 1–5 分。文档放进中性目录（看不出哪份用了 skill），第 2 位评审的 A / B 顺序对调，抵消位置偏好。

| 评审 | A / B | 用 skill S1 / S2 / S3 | 不用 skill S1 / S2 / S3 | 只能留一份 |
|---|---|---|---|---|
| 1 | A = 用 skill | 5 / 5 / 5 | 4 / 4 / 3 | 用 skill |
| 2 | A = 不用 skill（对调） | 5 / 5 / 5 | 4 / 5 / 3 | 用 skill |
| 3 | A = 用 skill | 4 / 5 / 4 | 4 / 5 / 4 | 用 skill |
| **中位数** | | **5 / 5 / 5** | **4 / 5 / 3** | **3 : 0** |

- **S1 差在「还缺我哪些决定」**：三位都指出，不用 skill 的那份把 v38 默认值、6.5 附近没有兜底、展示线没配不报错这些风险写成了散落的事实，没升成待决项，它的第 7 节留给读者拍的主要是「更新 PRD、核实口径」。用 skill 的那份第一屏就是 4 条带建议的待拍板。
- **S2 基本打平**：用 skill 的图多、关键数字放大；不用 skill 的图少但精（漏斗画了出局去向，页面图像真页面）。
- **S3 差在篇幅和逐条写法**：不用 skill 的那份 365 行，是原文 439 行的 83%，三位都说它没解决「太长看不完」；但它开头的「怎么读」一行和「三分钟看懂」被三位一致称赞。
- **选用 skill 的理由**（三位大意一致）：拍板的事在第一屏，篇幅约为对方的六成，扫加粗词就能定位。
- **用 skill 的那份被指出的短板**：页面部分最薄（三位都提：方框线框、「分类 1 分类 2」占位、4 处 ⏳ 待补）；阅读顺序倒了（第 3 位：待拍板满是「二跑、v38、整字段覆写」这类术语，能解释它们的漏斗图却在第 8 部分，标题还叫「召回 / 数据逻辑」，读者不会去翻）。

重跑那份没有做盲评。它和第一轮的差别靠客观考点和看图判断：页面示意改成了真实分类、真实标题和摘要、区域编号，状态和卡片细节各有一张示意图，打分 prompt 有维度 × 档位表——三位评审指出的「页面最薄」基本补上。阅读顺序的问题还在：它的待拍板第 1 条仍是「v26 打分器、v38、整字段覆盖、展示闸失去输入」，所以第二轮 S5 改了待拍板的写法。

### 3.3 不用 skill 的那份做得更好的地方（已吸收进 skill）

- **页面示意**：像真页面（真实分类名、真实文案、①–⑥ 编号配说明表），不是方框线框。
- **打分 prompt 的档位速查表**：五个维度 × 0–3 档一张表，「prompt 怎么判」答得更具体。
- **漏斗图画出局去向**：每一关右侧写「出局后会怎样」，比只画通过路径信息多。
- **入口**：开头一行「怎么读」把不同读者分到不同章节，接着一屏「三分钟看懂」先给机制再给细节。skill 没有照搬这个结构（用户定过待拍板置顶），改成要求待拍板每条能单独读懂、并链到展开它的部分。

## 6. 仍然没跑的

- **第二轮修复后没有再重跑生成，也没有再盲评**：第二轮只用脚本、构造样本和重跑的现成产出验证过。待拍板写法（#12）有没有真的让第一屏更好读，要等下一次真实使用。
- **重跑那份没做盲评**：它比第一轮好在哪，是客观考点加看图的判断。
- **真实页面截图链路**：精选的三组都起不了本地服务；`annotate.mjs` 和截图脚本模板只在 AI 搜索上真跑过。

- **主观评分全是模型评审**，没有人工抽检；只有一个留出样本（精选）。
