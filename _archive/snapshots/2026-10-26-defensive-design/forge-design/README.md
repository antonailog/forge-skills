# forge-design

管 DESIGN.md 和设计规则库

## 要解决的问题

让 AI 一边定设计一边写 CSS，设计决策还没想清楚就进了实现。前身 do-design 同时管设计和实现，一次按钮样式返工 4 轮，根因是最初的设计决策就错了，不是实现的问题。没人把关时，AI 做的界面还容易落进同一套模板：蓝紫渐变、三列彩色图标、一切居中。

## 运行方式

![forge-design 结构图](../../docs/diagrams/forge-design.jpg)

第 0 步按改动类型定级并请用户确认：新页面、新模块走 L1 完整设计，迭代走 L2 轻量审查，没有界面的直接交 forge-eng。布局、比例、密度这类要看见才能判断的决定，交给 forge-design-lab 在真实骨架上定。最后按 A–F 打分，没过线就回退（图中虚线）；过线后把 DESIGN.md 交给 forge-design-impl 实现。

## 关键设计

- **只做设计决策，不写产品代码**：设计和实现混在一起，AI 在设计思维和工程思维之间来回切换，两头都做不好
- **评分不过线就打回**：L1 低于 B 回到方案重做，L2 低于 C 升成 L1；同一模块反复迭代 3 次以上，直接按 L1 重新设计
- **比例不靠文字和效果图判断**：Image 2 只判断气质和风格，比例、密度在 forge-design-lab 的骨架上定，生图里的比例是画出来的
- **AI 模板痕迹直接点名**：按 10 个反面模式逐条查，如左边框高亮卡片、Emoji 当设计元素、千篇一律的 SaaS 区块节奏，查到就说，并计入评分
- **建议写成「把 X 改成 Y，因为 Z」**：不写「建议优化间距」；5–10 个记录充分的发现，好过 20 个模糊观察

## 其他

- 前提：Python 3 跑 search.py，查自带的规则库（99 条 UX 规则、161 套配色、73 组字体搭配等 CSV），不依赖外部服务
- 注意：大需求下的子模块要先读父页面的 DESIGN.md，配色、字体、间距、圆角对不上的要改，或者拿到用户明确许可
